# 游戏开发中的阴影实现原理详解

阴影（Shadow）是实时渲染中非常重要的一部分，它不仅决定物体的明暗关系，还能帮助玩家判断物体与地面的距离、空间层次以及光源方向。

在 Unity、Unreal Engine 等游戏引擎中，常见的阴影实现方案主要有：

1. 圆片阴影（Blob Shadow）：使用一张半透明的圆形贴图模拟阴影。
    
2. 平面投影阴影（Planar Shadow）：根据光照方向，将模型顶点投影到指定平面。
    
3. 阴影映射（Shadow Mapping）：从光源视角渲染深度图，再通过深度比较判断阴影。
    

此外，现代大型游戏还会使用 CSM、PCF、PCSS、虚拟阴影贴图（Virtual Shadow Maps）、屏幕空间接触阴影等技术。

我们先理解三种基础方案，再深入讲解 Shadow Map 的问题及其优化算法。

## 一、三种基础阴影方案的区别

|对比维度|圆片阴影 Blob|平面阴影 Planar|Shadow Map|
|---|---|---|---|
|实现原理|绘制半透明贴图|将模型投影到平面|光源深度比较|
|是否使用真实模型轮廓|否|是|是|
|是否支持任意接收表面|否，需特殊适配|通常只支持指定平面|是|
|是否支持自阴影|否|否|是|
|是否支持动态光源|可以，但不精确|支持|支持|
|阴影精度|低|中|高|
|GPU 开销|很低|较低|相对较高|
|典型用途|手游、角色脚底阴影|低成本角色投影|场景、建筑、角色实时阴影|

这里最核心的区别是：

圆片阴影是模拟阴影，平面阴影是几何投影，Shadow Map 是进行光照遮挡判断。

## 二、圆片阴影（Blob Shadow）

### 2.1 基本原理

圆片阴影是最简单的一种实时阴影模拟方式。

它不需要知道物体的实际模型形状，也不需要计算光线是否被遮挡。

实现方法就是：

在角色脚下放置一个 Quad（四边形），使用带有透明渐变的圆形纹理，模拟角色与地面接触产生的阴影。

使用 Alpha Blend 渲染阴影

### 2.2 阴影如何跟随角色移动

最简单的实现方式是在角色脚下放一个 Quad，随着角色移动同步调整 Quad 的位置。

但是这种方案存在问题：

假设角色跳到空中，脚下的阴影仍然应该在地面上，而不是跟随角色一起升高。

因此实际项目中，通常使用射线检测（Raycast）寻找地面。

```
using UnityEngine;

public class BlobShadow : MonoBehaviour
{
    // 角色 Transform
    public Transform target;

    // 用于显示阴影的 Quad
    public Transform shadowQuad;

    // 阴影材质
    public Material shadowMaterial;

    // 阴影最大有效高度
    public float maxHeight = 5.0f;

    // 阴影默认大小
    public float baseSize = 1.0f;

    void LateUpdate()
    {
        // 从角色上方一点开始发射射线
        Vector3 origin = target.position + Vector3.up * 0.5f;

        // 向下检测地面
        if (Physics.Raycast(
            origin,
            Vector3.down,
            out RaycastHit hit,
            maxHeight + 0.5f))
        {
            // 阴影位于地面稍微上方
            // 防止与地面发生 Z-Fighting（深度冲突）
            shadowQuad.position =
                hit.point + hit.normal * 0.01f;

            // 将 Quad 的局部法线方向对齐地面法线
            // 假设 Quad 在本地 XY 平面，正面朝向 +Z
            shadowQuad.rotation =
                Quaternion.FromToRotation(
                    Vector3.forward,
                    hit.normal);

            // 计算角色到地面的垂直距离
            float height =
                Mathf.Max(
                    0,
                    target.position.y - hit.point.y);

            // 将高度归一化到 0~1
            float t = Mathf.Clamp01(height / maxHeight);

            // 角色越高，阴影越大
            float size = Mathf.Lerp(
                baseSize,
                baseSize * 1.5f,
                t);

            shadowQuad.localScale =
                new Vector3(size, size, 1);

            // 角色越高，阴影越淡
            float alpha = Mathf.Lerp(0.6f, 0.0f, t);

            // 实际项目推荐使用 MaterialPropertyBlock
            // 避免频繁实例化材质
            shadowMaterial.SetFloat("_ShadowAlpha", alpha);

            shadowQuad.gameObject.SetActive(true);
        }
        else
        {
            shadowQuad.gameObject.SetActive(false);
        }
    }
}
```

这是一个演示原理的简化实现。

实际项目还需要考虑共享材质、地面 LayerMask、射线穿透以及角色在斜坡或平台边缘时的显示问题。对于大量角色，可以将检测频率降低，或者直接利用角色已有的地面检测数据。

### 2.3 圆片阴影的 Shader 原理

圆片阴影本质上就是一个透明材质。

可以使用纹理，也可以直接在 Shader 中通过数学公式生成一个渐变圆形。

例如：

```
// UV 范围为 0~1
float2 uv = input.uv;

// 将 UV 中心移动到 (0,0)
// 原来的 (0.5,0.5) 现在是 (0,0)
float2 centerUV = uv - 0.5;

// 计算当前像素到中心的距离
float dist = length(centerUV);

// smoothstep 实现边缘平滑
// 0.1 内基本不透明
// 0.5 外完全透明
float alpha = 1.0 - smoothstep(0.1, 0.5, dist);

// 乘上整体透明度
alpha *= _ShadowAlpha;

// 输出黑色半透明阴影
return float4(0, 0, 0, alpha);
```

其核心数学公式为：

$$
d=\sqrt{(u-0.5)^2+(v-0.5)^2}
$$

$$
\alpha=1-\operatorname{smoothstep}(r_1,r_2,d)
$$

其中 \(d\) 是当前纹理坐标到中心的距离，\(r_1\) 是开始渐变的半径，\(r_2\) 是完全透明的半径。

最终通过 Alpha 混合：

$$
C_{final}=\alpha C_{shadow}+(1-\alpha)C_{background}
$$

因为阴影颜色通常为黑色，所以：

$$
C_{final}=(1-\alpha)C_{background}
$$

地面就会变暗。

需要注意，这种方案只是将地面颜色压暗，不会真正参与光照计算。

### 2.4 圆片阴影的优缺点

优点： GPU 开销极低，不需要额外的 Shadow Pass，也不需要保存深度贴图，非常适合角色数量多的移动端游戏。对于只需要表达角色接地关系的场景，效果通常已经足够。

缺点： 阴影不能反映人物、武器等实际轮廓，不会产生真实自阴影，也无法准确表示物体与其他物体之间的遮挡关系。对于台阶、悬崖和复杂地面，还需要额外的裁剪或贴合逻辑。

## 三、平面阴影（Planar Shadow）

平面阴影比圆片阴影更进一步。

它不是使用固定的圆形，而是根据光照方向，将模型的真实几何形状投影到一个平面上。

因此平面阴影能够保留角色的大致轮廓，例如人物的手臂、腿、武器以及身体姿态。

### 3.1 平面阴影的工作原理

假设：

- 地面为 \(Y=0\)。
    
- 模型上的顶点为 \(P=(x,y,z)\)。
    
- 光线传播方向为 \(D=(D_x,D_y,D_z)\)。
    
- 我们需要计算顶点 P 沿着光线方向投影到地面的位置 Q。
    

从 P 沿着方向 D 发射一条射线：

$$
Q=P+tD
$$

展开：

$$
\begin{cases} Q_x=P_x+tD_x\\ Q_y=P_y+tD_y\\ Q_z=P_z+tD_z \end{cases}
$$

因为阴影必须落在地面上，所以：

$$
Q_y=0
$$

得到：

$$
P_y+tD_y=0
$$

因此：

$$
\boxed{t=-\frac{P_y}{D_y}}
$$

代入前面的公式：

$$
\boxed{ \begin{aligned} Q_x&=P_x-\frac{P_yD_x}{D_y}\\ Q_y&=0\\ Q_z&=P_z-\frac{P_yD_z}{D_y} \end{aligned} }
$$

这就是最基础的平面阴影投影公式。

例如，假设有一个模型顶点：

$$
P=(2,3,1)
$$

光线方向为：

$$
D=(1,-2,0)
$$

那么：

$$
t=-\frac{3}{-2}=1.5
$$

最终：

$$
Q=(3.5,0,1)
$$

说明这个顶点的阴影位于地面上的 (3.5, 0, 1)。

只要对模型所有顶点执行相同的投影运算，就能得到整个模型在地面上的投影形状。

这里的 D 是光线传播方向，也就是从光源指向场景的方向。如果使用的是 Shader 中常见的“从表面指向光源”的 LightDirection，则需要先取反。

### 3.2 为什么平面阴影适合 GPU 实现

因为平面阴影本质上是顶点位置变换（Vertex Transformation）。

一个模型有多少个顶点，只需要在 Vertex Shader 中对每个顶点做一次投影。

常见做法是把角色绘制两次：

第一次正常绘制角色，第二次使用专门的平面阴影材质绘制同一个模型。

第二次绘制时，Vertex Shader 会把所有顶点投影到地面，Fragment Shader 则统一输出半透明黑色。

### 3.3 平面阴影 HLSL 实现

下面以 Unity 常用的 HLSL 风格编写，重点展示核心原理。

先假设地面高度为 `_GroundY`，光线始终向下传播。

```
// 顶点着色器输入
struct Attributes
{
    // 模型本地坐标
    float4 positionOS : POSITION;
};

// 顶点着色器输出
struct Varyings
{
    // 裁剪空间坐标
    float4 positionCS : SV_POSITION;
};

// 光线传播方向（世界空间）
float3 _LightDir;

// 地面高度
float _GroundY;

// 阴影偏移，防止和地面深度冲突
float _ShadowBias;

// 模型的世界变换矩阵
float4x4 _ObjectToWorld;

// 摄像机的 ViewProjection 矩阵
float4x4 _ViewProjection;

// 顶点着色器
Varyings vert(Attributes input)
{
    Varyings output;

    // 第一步：模型空间 -> 世界空间
    float4 worldPos = mul(
        _ObjectToWorld,
        input.positionOS
    );

    // 第二步：获取光照方向
    float3 lightDir = normalize(_LightDir);

    // 第三步：计算投影距离
    // 光线方向的 Y 分量不能为 0
    // 否则光线与地面平行，没有有限的交点
    float t = (_GroundY - worldPos.y) / lightDir.y;

    // 第四步：将顶点沿光照方向投影到地面
    float3 shadowPos =
        worldPos.xyz + t * lightDir;

    // 第五步：添加微小偏移
    // 防止阴影和地面 Z-Fighting
    shadowPos.y = _GroundY + _ShadowBias;

    // 第六步：世界空间 -> 裁剪空间
    output.positionCS = mul(
        _ViewProjection,
        float4(shadowPos, 1.0)
    );

    return output;
}

// 像素着色器
float4 frag(Varyings input) : SV_Target
{
    // 输出黑色半透明阴影
    return float4(0.0, 0.0, 0.0, 0.4);
}
```

注意，这段代码是独立的数学示例，不是可以直接复制到所有 Unity 渲染管线的完整 Shader。实际使用需要对接对应管线的变换矩阵、Pass 和材质参数。

对应的常见渲染状态：

```
// 启用透明混合
Blend SrcAlpha OneMinusSrcAlpha

// 阴影不写入深度缓冲
ZWrite Off

// 仍然进行深度检测
ZTest LEqual

// 投影后的三角形可能发生翻转
// 双面绘制避免部分阴影消失
Cull Off
```

这些设置的目的分别是让阴影可以半透明、避免覆盖场景深度、尽可能防止透过前面的物体显示，并处理投影几何面的朝向变化。

### 3.4 斜面或者任意平面的投影公式

前面的例子要求地面必须是 \(Y=0\)。

如果我们要把阴影投射到任意平面，可以使用平面方程：

$$
Ax+By+Cz+D=0

$$
令：

$$
N=(A,B,C)
$$

平面方程可以写成：

$$
N\cdot P+D=0
$$

假设需要投影的模型顶点是 P，光照方向是 L，投影点为：

$$
Q=P+tL
$$

将 Q 代入平面方程：

$$
N\cdot(P+tL)+D=0
$$

展开：

$$
N\cdot P+t(N\cdot L)+D=0
$$

所以：

$$
t=-\frac{N\cdot P+D}{N\cdot L}
$$

最终得到平面阴影的通用公式：

$$
\boxed{ Q=P-\frac{N\cdot P+D}{N\cdot L}L }
$$

这个公式非常重要。

它意味着只要知道平面法线和平面方程，就能把模型顶点投影到任意方向的平面上，而不再局限于水平地面。

对应 HLSL：

```
float3 ProjectToPlane(
    float3 worldPos,   // 原始顶点的世界坐标
    float3 lightDir,   // 光线传播方向
    float3 planeNormal,// 平面法线
    float planeD       // 平面方程中的 D
)
{
    // 光线与平面法线的点积
    float denominator =
        dot(planeNormal, lightDir);

    // denominator 接近 0 时
    // 表示光线与平面近似平行
    // 调用方应跳过此次投影
    // 此处假定调用前已完成有效性检查

    // 计算射线与平面的交点参数
    float t = -(
        dot(planeNormal, worldPos) + planeD
    ) / denominator;

    // 返回投影后的世界坐标
    return worldPos + t * lightDir;
}
```

对于局部斜坡，可以将斜坡近似成一个平面，然后应用上述公式。

但对于连续起伏的地形，这种方法依然不能产生完全正确的阴影，因为一个投影平面并不能描述整个复杂地形。

### 3.5 平面阴影使用点光源时怎么办？

前面讨论的是方向光（Directional Light），也就是所有光线平行的情况。

对于点光源（Point Light），光线会从光源位置向外发散。

设：

- 光源位置为 S。
    
- 模型顶点为 P。
    
- 地面投影点为 Q。
    

射线为：

$$
Q=S+t(P-S)
$$

将其代入平面方程：

$$
N\cdot Q+D=0
$$

可得：

$$
\boxed{ t=-\frac{N\cdot S+D}{N\cdot(P-S)} }
$$

进而求出 Q。

需要注意：点光源情况下，投影点必须位于光源经过模型顶点的射线后方，即通常要求 \(t\ge1\)，而且分母不能接近零。否则这个数学交点不代表实际的投射阴影。

### 3.6 平面阴影的主要问题

问题一：无法产生自阴影。

虽然模型的轮廓会被投影到地面，但是角色身上的其他部位并不会因为遮挡而变暗。

例如角色举起一把剑，剑可以在地面形成阴影，却无法直接在角色身体上形成正确的阴影。

问题二：无法正确适应复杂地形。

平面阴影只能落在指定平面上。遇到台阶、山坡、岩石或者高低错落的平台，就需要额外的接收面或投影处理。

问题三：容易出现阴影叠加和深度冲突。

投影后的多个三角形可能发生重叠，在 Alpha Blend 下会重复混合，造成局部阴影特别黑。

工程中通常会使用 Stencil Buffer（模板缓冲）、单独的阴影遮罩或其他方法，限制同一阴影区域被重复着色。

问题四：额外的几何绘制开销。

角色通常需要额外绘制一次经过投影的 Mesh。阴影 Pass 虽然较简单，但大量高面数、蒙皮角色仍然会增加顶点处理和蒙皮成本。

总结：平面阴影适合在有限接收平面上，用较低的成本获得真实模型轮廓。

它不是真实光照遮挡算法，而是一种非常实用的几何投影技巧。

## 四、Shadow Mapping（阴影映射）

Shadow Mapping 是现代实时游戏中最经典、最重要的动态阴影技术之一。

Unity、UE 的传统实时阴影系统，以及很多高级阴影算法，都是建立在 Shadow Mapping 的基本思想之上的。

### 4.1 Shadow Mapping 的核心原理

Shadow Mapping 的本质是：从光源视角记录物体深度，再判断某个像素与光源之间是否存在更近的遮挡物。

先看一张原理图。

这两个 Pass 是理解 Shadow Mapping 的关键。

### 4.2 第一个 Pass：生成 Shadow Map

假设场景中有一个立方体和一个地面。

光源位于立方体上方。

我们从光源位置渲染整个场景，但是不需要计算颜色、材质或者复杂光照，只需要记录深度。

例如光源视角的深度值如下：

<img width="737" height="812" alt="image" src="https://github.com/user-attachments/assets/b6aa1c19-e50f-4704-814f-577af75afc9d" />


在这个例子中，立方体比地面更接近光源。

假设立方体顶部距离光源为 3 米，地面距离光源为 8 米。

对于被立方体遮挡的区域，Shadow Map 保存的是立方体深度 3，而不是后面的地面深度 8。

原因很简单：

深度测试只保留当前光源视角下最近的可见表面。

这也是为什么 Shadow Map 本质上是一张深度纹理。

### 4.3 第二个 Pass：判断像素是否处于阴影

现在从正常摄像机视角绘制场景。

当绘制地面某个像素 P 时，需要判断这个像素能否直接看到光源。

具体操作是将 P 转换到光源的投影空间，找到它在 Shadow Map 中对应的位置。

假设得到：

当前地面像素的深度：

$$
Depth_{current}=8
$$

而 Shadow Map 中保存的深度：

$$
Depth_{shadow}=3
$$

因为：

$$
8>3
$$

这说明在光源与地面像素之间，还有一个距离光源更近的物体。

所以当前地面像素处于阴影中。

再换一个位置：

$$
Depth_{current}=8
$$

$$
Depth_{shadow}=8
$$

这两个深度相等，说明光源到当前地面像素之间没有其他更近的遮挡物，因此当前像素可以接受光照。

核心公式为：

$$
\boxed{ Shadow(P)= \begin{cases} 1 & d_{current}>d_{shadow}+bias\\ 0 & d_{current}\le d_{shadow}+bias \end{cases} }
$$

其中：

$$
d_{current}：当前像素在光源空间下的深度。
$$
    
$$
d_{shadow}：Shadow Map 中记录的深度。
$$
    
$$
bias：阴影深度偏移，用来避免浮点精度和离散采样导致的错误自遮挡。
$$
    
$$
Shadow(P)=1：当前像素处于阴影中。
$$
    
$$
Shadow(P)=0：当前像素没有被遮挡。
$$
    

这里假设深度越大代表距离光源越远。对于 Reversed-Z（反向深度）等实现，底层比较关系需要相应调整。

### 4.4 世界空间如何转换到光源空间？

这是 Shadow Mapping 实现过程中非常关键的数学步骤。

正常渲染时，模型顶点通常经历以下变换：

$$
P_{clip}=P_{camera}V_{camera}P_{projection}
$$

这里用行向量表示，以便说明概念。具体 Shader 代码使用何种矩阵乘法顺序，取决于采用的行向量或列向量约定。

生成 Shadow Map 时，使用的是光源的 View 和 Projection 矩阵。

用列向量表示：

$$
\boxed{ P_{lightClip}=M_{lightProj}M_{lightView}P_{world} }
$$

随后进行透视除法：

$$
P_{NDC}= \frac{P_{lightClip}.xyz}{P_{lightClip}.w}
$$

NDC（Normalized Device Coordinates，归一化设备坐标）中，X 和 Y 可以转换成 Shadow Map 的 UV 坐标。

在常见的 \([-1,1]\) X/Y NDC 约定下：

$$
UV_{shadow}=P_{NDC}.xy\times0.5+0.5
$$

对应 HLSL：

```
// 计算当前世界坐标在光源空间中的位置
float4 lightClipPos = mul(
    _LightViewProjection,
    float4(worldPos, 1.0)
);

// 进行透视除法
// 将裁剪空间坐标转换成 NDC
float3 lightNDC =
    lightClipPos.xyz / lightClipPos.w;

// 将 XY 从 -1~1 转换到 0~1
float2 shadowUV =
    lightNDC.xy * 0.5 + 0.5;

// Z 是当前像素在光源投影空间中的深度
// 需要转换到 Shadow Map 使用的深度约定
float currentDepth =
    ConvertLightDepthTo01(lightNDC.z);
```

需要注意几个细节：OpenGL 与 D3D/Vulkan 的深度范围约定可能不同；Render Target 的 UV Y 方向可能需要翻转；引擎也可能使用 Reversed-Z。

因此真实项目中，通常直接使用渲染管线提供的光源空间坐标转换函数，而不是自己硬编码所有坐标转换规则。

### 4.5 Shadow Map 的 Shader 核心实现

先看一个简化的深度比较函数。

```
Texture2D<float> _ShadowMap;
SamplerState sampler_ShadowMap;

// 返回值：
// 1 表示接受直接光照
// 0 表示处于阴影中
float CalculateShadow(
    float3 worldPos
)
{
    // 1. 世界空间 -> 光源裁剪空间
    float4 lightPos = mul(
        _LightViewProjection,
        float4(worldPos, 1.0)
    );

    // 2. 透视除法
    float3 ndc = lightPos.xyz / lightPos.w;

    // 3. 转换到 Shadow Map 的 UV 坐标
    float2 uv = ndc.xy * 0.5 + 0.5;

    // 4. 转换当前像素的深度
    float currentDepth =
        ConvertLightDepthTo01(ndc.z);

    // 5. 判断像素是否位于 Shadow Map 有效范围
    // 范围之外的行为由具体阴影方案决定
    if (uv.x < 0 || uv.x > 1 ||
        uv.y < 0 || uv.y > 1)
    {
        return 1.0;
    }

    // 6. 从 Shadow Map 读取深度
    float shadowDepth =
        _ShadowMap.SampleLevel(
            sampler_ShadowMap,
            uv,
            0
        ).r;

    // 7. 阴影偏移
    float bias = 0.001;

    // 8. 深度比较
    // 当前像素比记录的深度更远
    // 说明它被其他物体遮挡
    if (currentDepth > shadowDepth + bias)
    {
        return 0.0;
    }

    // 当前像素没有被遮挡
    return 1.0;
}
```

其中 `ConvertLightDepthTo01` 是示意函数，需要由具体图形 API 的深度格式决定；该示例也假设 Shadow Map 的深度是正向 0～1，并且使用点采样读取深度。

最终计算光照时：

```
// 查询当前像素的阴影可见度
float shadowAttenuation =
    CalculateShadow(worldPos);

// 基础环境光照
float3 ambient = albedo * ambientColor;

// 直接光照（例如漫反射 + 镜面反射）
float3 directLighting =
    CalculateDirectLighting(...);

// 阴影只衰减被当前光源遮挡的直接光照
float3 finalColor =
    ambient + directLighting * shadowAttenuation;
```

这里还有一个重要知识点：

阴影不代表该像素必须是纯黑色。

实际游戏中，处于阴影的物体依然可能接受环境光、天空光、间接漫反射、其他光源等照明。

所以通常不能简单地把整个最终颜色乘以 0。

# 六、Shadow Mapping 常见问题及优化

Shadow Mapping 原理并不复杂，但要在真正的商业游戏里获得高质量的阴影，需要解决很多问题。

## 6.1 Shadow Acne（阴影痤疮 / 自阴影伪影）

这是 Shadow Mapping 最经典的问题之一。

<img width="640" height="360" alt="image" src="https://github.com/user-attachments/assets/8ebb4709-fee1-4037-b9f9-f99e2dcd3745" />


假设一个原本接受光照的平面，在光源视角下的真实深度是：

$$
d=0.5
$$

但是 Shadow Map 的分辨率有限，离散采样和深度精度会产生误差。

可能出现：

$$
d_{current}=0.5001
$$

$$
d_{shadow}=0.5000
$$

通过深度比较：

$$
0.5001>0.5000
$$

于是系统错误地认为当前像素被其他物体遮挡，导致原本明亮的区域出现黑色条纹、斑点。

这个现象就是 Shadow Acne。

### 解决方法一：Depth Bias（深度偏移）

简单来说，就是给深度比较增加一个容差。

原来的判断：

```
bool isShadow = currentDepth > shadowDepth;
```

修改后：

```
// Bias：深度偏移
float bias = 0.001;

// 允许一定的浮点误差
bool isShadow =
    currentDepth > shadowDepth + bias;
```

但这里存在一个问题：

不同表面与光线的夹角不同，所需要的偏移量也不同。

因此我们还需要斜率相关的偏移。

### 解决方法二：Slope-Scale Bias（斜率相关偏移）

当一个表面与光照方向接近平行时，深度变化相对明显，更容易产生 Shadow Acne。

可以根据表面法线和光照方向来调整 Bias。

```
// N：当前表面法线
// L：从当前表面指向光源的方向
float3 N = normalize(normalWS);
float3 L = normalize(lightDirWS);

// NdotL 越接近 1
// 表示表面越朝向光源
float NdotL = saturate(dot(N, L));

// 计算一个近似的角度相关偏移
float bias = max(
    0.001 * (1.0 - NdotL),
    0.0001
);
```

这个公式是一种常见的角度相关 Bias 近似。

严格来说，GPU 硬件中的 Slope-Scale Depth Bias 是按照光源投影深度相对于屏幕 X/Y 的最大斜率计算的，和上面这种基于法线的近似不完全相同。

实际商业项目往往会结合常量 Bias、斜率 Bias 和法线偏移共同处理。

## 6.2 Peter Panning（阴影悬浮）

Depth Bias 并不是越大越好。

<img width="1313" height="552" alt="image" src="https://github.com/user-attachments/assets/a349a14d-b73d-4f90-a16d-dd27ac85f204" />


假设 Bias 设置过大，那么原本应该被遮挡的像素也有可能通过深度比较。

表现为：

物体脚底与地面阴影之间出现一段明显的空隙，看上去像物体悬浮在空中。

这就是 Peter Panning。

|Bias 设置|可能的效果|
|---|---|
|太小|Shadow Acne，自阴影斑点|
|合适|阴影正常贴合物体|
|太大|Peter Panning，阴影脱离物体|

因此 Bias 的调整通常需要在这两种问题之间取得平衡。

### 6.3 Normal Bias（法线偏移）

除了沿深度方向增加偏移，还可以沿表面法线方向偏移采样位置。

```
// 当前像素的世界空间坐标
float3 worldPos;

// 当前表面的世界空间法线
float3 normalWS;

// 法线偏移参数
float normalBias = 0.02;

// 沿表面法线方向移动采样位置
float3 biasedWorldPos =
    worldPos + normalize(normalWS) * normalBias;

// 使用偏移后的位置查询阴影
float shadow =
    CalculateShadow(biasedWorldPos);
```

它可以减少部分自阴影伪影，但同样可能造成阴影位置变化、薄物体漏光和接触处脱离的问题。

在 Unity 和 UE 中，Bias 参数的实际单位、含义以及应用阶段并不完全相同。

## 七、PCF：Shadow Map 软阴影实现

### 7.1 为什么 Shadow Map 的边缘会有锯齿？

假设 Shadow Map 分辨率为：

$$
1024\times1024
$$

每个 Shadow Texel（阴影纹素）对应光源视角下的一小块场景区域。

当这块区域被投影到屏幕时，可能覆盖多个屏幕像素。

由于 Shadow Map 的深度值是离散的，多个相邻屏幕像素可能得到完全一样的阴影判断。

这样一来，阴影边缘就容易呈现明显的阶梯状。

我们可以提高 Shadow Map 分辨率，但这会增加显存、深度绘制开销和采样带宽。

因此产生了 PCF。

### 7.2 PCF 原理

PCF 的完整名称是：

Percentage Closer Filtering（百分比渐近过滤）

最核心的思想是：

不再仅仅对 Shadow Map 做一次深度比较，而是对周围多个位置分别进行深度比较，最后求平均值。

例如采用 3×3 的采样区域：

<img width="737" height="327" alt="image" src="https://github.com/user-attachments/assets/78ece6f0-bff9-4fb1-add9-4229373400bc" />


对应公式：

$$
\boxed{ Visibility(P)=\frac{1}{N}\sum_{i=1}^{N}V_i(P) }
$$

其中 \(V_i(P)\) 表示第 i 个 Shadow Map 采样点的深度比较结果。

例如 9 个采样点中有 6 个认为当前表面没有被遮挡：

$$
Visibility(P)=\frac{6}{9}\approx0.667
$$

此时只保留大约 66.7% 的直接光照，产生柔和的边缘。

这就是 PCF 软阴影的基础。

### 7.3 PCF 的 HLSL 实现

下面实现一个最简单的 3×3 PCF。

```
// Shadow Map 深度贴图
Texture2D<float> _ShadowMap;

// 为了避免先过滤深度再比较
// 此处假设使用点采样
SamplerState sampler_PointClamp;

// Shadow Map 的分辨率
float2 _ShadowMapSize;

// 当前像素的 Shadow UV 和深度
float CalculatePCF(
    float2 shadowUV,
    float currentDepth
)
{
    // 一个 Shadow Texel 在 UV 空间中的大小
    float2 texelSize = 1.0 / _ShadowMapSize;

    // 累计可见度
    float visibility = 0.0;

    // 深度偏移
    float bias = 0.001;

    // 3×3 共 9 次深度比较
    for (int x = -1; x <= 1; x++)
    {
        for (int y = -1; y <= 1; y++)
        {
            // 每次采样相邻的 Shadow Texel
            float2 offset = float2(x, y) * texelSize;

            // 读取该位置记录的深度
            float shadowDepth = _ShadowMap.SampleLevel(
                sampler_PointClamp,
                shadowUV + offset,
                0
            ).r;

            // 当前像素没有被遮挡，累计 1
            // 被遮挡则累计 0
            visibility +=
                (currentDepth <= shadowDepth + bias)
                ? 1.0
                : 0.0;
        }
    }

    // 对 9 次结果取平均值
    return visibility / 9.0;
}
```

这是教学实现。实际项目一般会使用硬件 Shadow Comparison Sampler（深度比较采样器），或者对采样位置和采样次数进行优化。

PCF 的主要优点是实现相对容易，性能可以通过控制样本数进行调节。

但是需要特别注意：

PCF 主要是一种阴影过滤技术，并不意味着能够自动产生符合真实面积光源几何关系的半影。

使用固定大小的 PCF 核时，物体贴近地面和远离地面，阴影边缘可能都具有差不多的模糊宽度。

而真实世界的面积光源软阴影并不是这样。

## 八、PCSS：距离越远，阴影越柔和

PCSS 全称：

Percentage Closer Soft Shadows（百分比渐近软阴影）

它是在 Shadow Mapping 和 PCF 基础上发展出来的软阴影算法。

PCSS 的目标之一就是实现接近真实面积光源的半影变化：

物体距离接收面越远，阴影边缘往往越宽；当物体靠近接收面时，阴影边缘会变得更清晰。

PCSS 通常包含三个阶段。

### 8.2 半影宽度计算

在平行平面近似模型中，PCSS 的典型半影估算公式为：

$$
\boxed{ w_{penumbra}= \frac{d_{receiver}-d_{blocker}}{d_{blocker}} \cdot w_{light} }
$$

其中：

$$
d_{receiver}：接收面到光源的距离。
$$
    
$$
d_{blocker}：遮挡物到光源的距离。
$$
    
$$
w_{light}：光源的有效尺寸。
$$
    
$$
w_{penumbra}：估算的半影宽度。
$$
    

可以从公式看出：

当接收面距离遮挡物越远时：

$$
d_{receiver}-d_{blocker}\uparrow
$$

半影宽度增大。

因此阴影边缘逐渐变软。

而当遮挡物靠近接收面：

$$
d_{receiver}\approx d_{blocker}
$$

那么：

$$
w_{penumbra}\approx0
$$

阴影边缘会变得比较清晰。

这类效果也被称为 Contact Hardening Shadow（接触硬化阴影）。

上述公式只是简化的几何估算，实际 Shader 还需要根据投影类型，将半影宽度换算到 Shadow Map 的 UV 采样半径。

### 8.3 PCF 与 PCSS 对比

|对比|PCF|PCSS|
|---|---|---|
|核心原理|多次深度比较取平均|遮挡搜索、半影估算、可变核过滤|
|是否可以产生软阴影|是|是|
|是否模拟距离相关的半影变化|固定核通常不能|可以近似实现|
|性能开销|相对较低|通常更高|
|阴影效果|过滤后的柔和边缘|更自然的接触硬化软阴影|

所以可以这样记忆：

PCF 解决阴影边缘的平滑过滤问题，PCSS 则进一步根据遮挡几何关系控制边缘柔和程度。

## 九、CSM：级联阴影映射

CSM 的完整名称是：

Cascaded Shadow Maps（级联阴影贴图）

它是开放世界游戏以及大范围方向光实时阴影中非常重要的一项技术。

### 9.1 为什么需要 CSM？

假设有一张：

$$
2048\times2048
$$

的 Shadow Map。

如果这张 Shadow Map 只需要覆盖角色周围 20 米的区域，那么阴影精度会比较高。

但是如果要求它覆盖整个 1000 米的场景，分辨率仍然是 2048×2048，那么单位世界空间长度能够分配到的阴影纹素数量就会急剧下降。

导致角色脚下、树叶边缘等阴影变得粗糙。

这就是 Shadow Map 的分辨率分配问题。

对于摄像机透视投影，还存在 Perspective Aliasing（透视混叠）：不同距离区域在屏幕空间中所需的阴影分辨率并不均匀。

### 9.2 CSM 的实现原理

CSM 的核心思想非常简单：

根据摄像机与物体的距离，将摄像机视锥划分成多个区域，为每个区域分别生成 Shadow Map。

例如将摄像机的可见范围分成 4 级：

<img width="736" height="300" alt="image" src="https://github.com/user-attachments/assets/db5e2650-5670-4071-80e8-ca7bb82dd427" />


|   |   |   |
|---|---|---|
|C0|0～10m|最高世界空间纹素密度|
|C1|10～30m|较高精度|
|C2|30～60m|中等精度|
|C3|60～100m|较低精度|


这样做的好处是：

离摄像机较近的区域，Shadow Map 只需要覆盖很小的世界空间，因此能够获得更高的世界空间精度。

离摄像机较远的区域，Shadow Map 覆盖更大的范围，因此精度相对降低。

这在视觉上更加合理，因为玩家通常更加关注靠近摄像机的角色和场景细节。

### 9.3 CSM 的具体渲染流程

对于每一级 Cascade：

首先计算对应的摄像机视锥切片（Frustum Slice）。

然后将这个视锥切片转换到光源空间。

接下来计算能够包围这部分空间的正交投影范围，并生成对应的光源 ViewProjection 矩阵。

最后将这一范围内可能投射阴影的物体渲染到对应的 Shadow Map 中。

正式渲染场景时，根据当前像素的摄像机深度，选择对应的 Cascade 并执行 Shadow Map 深度比较。

部分实现还会在相邻 Cascade 的边界处进行混合，避免产生明显的分界线。

Unity 的阴影级联实现也是通过将摄像机可见区域拆分为多个阴影覆盖区来改善精度分配的。

### 9.4 CSM 的优缺点

优点： 不需要无限制提高单张 Shadow Map 的分辨率，就可以显著提高摄像机附近的方向光阴影质量。非常适合第三人称角色、室外场景和大型地图。

缺点： 需要为多个 Cascade 准备阴影深度数据，增加几何绘制、阴影缓存管理以及采样处理的成本。相邻 Cascade 的分界也可能造成阴影跳变、闪烁或者精度不连续。

此外，当摄像机移动时，光源投影区域不断发生变化，Shadow Map 纹素与世界空间位置之间的对应关系可能产生抖动。

工程中常用 Texel Snapping（纹素对齐）以及稳定包围区域等方法来减少这种现象。

## 十、VSM：两种容易混淆的阴影技术

这里需要特别注意：VSM 在阴影领域可能代表两种不同的技术。

### 10.1 Variance Shadow Maps（方差阴影贴图）

传统 Shadow Map 保存的是一个深度值。

Variance Shadow Maps 除了保存深度的一阶矩之外，还保存深度的二阶矩。

$$
M_1=E[z]
$$

$$
M_2=E[z^2]
$$

于是可以求出深度方差：

$$
\sigma^2=E[z^2]-E[z]^2
$$

然后利用概率上界来估计阴影可见度。

它的一个重要特点是：

可以对深度矩信息先进行普通纹理过滤，再估计阴影。

传统 Shadow Map 如果直接对深度做线性过滤，再进行单次比较，通常不能得到正确的 PCF 结果。

方差阴影贴图则允许对保存的矩信息进行双线性过滤、模糊以及 Mipmap 等操作。

但它容易出现 Light Bleeding（漏光）问题，也就是本来应该比较暗的区域被错误地估算为接受了一部分光照。

EVSM（Exponential Variance Shadow Maps，指数方差阴影贴图）等方法是这条技术路线上的改进。

### 10.2 Virtual Shadow Maps（虚拟阴影贴图）

这个技术在 UE5 中尤其重要。

Virtual Shadow Maps 同样简称 VSM，但它和刚才的 Variance Shadow Maps 完全不是一回事。

UE5 的虚拟阴影贴图主要解决的是超高分辨率实时阴影的存储、更新和渲染管理问题。

它借鉴了虚拟纹理的基本思想：

不一次性维护一张完整、巨大且所有区域都有效的阴影深度纹理，而是将虚拟阴影空间分页，按需维护物理页。

虚拟阴影贴图通常还会结合页面缓存、脏页检测、按需更新以及不同层次的投影区域来减少不必要的工作。

它对高精度 Nanite 几何体和动态大型场景尤其重要，但需要注意：

虚拟化只是改善资源分配与更新方式，并不意味着它天然没有阴影绘制成本。大范围动态变化、缓存大量失效、非 Nanite 几何复杂度过高等情况，依然可能造成明显性能问题。

Epic 官方文档中也明确区分了传统 Shadow Maps、Virtual Shadow Maps、Ray-Traced Shadows 和 Distance Field Shadows。

## 十一、Shadow Map 的性能开销来自哪里？

Shadow Map 的性能开销通常包含两大部分。

### 11.1 生成阶段的开销

主要来自从光源视角绘制场景几何体。

即使 Shadow Pass 不进行完整材质和光照计算，也仍然可能需要执行：

顶点变换、骨骼蒙皮、几何裁剪、光栅化、深度测试和深度写入。

对于使用 Alpha Clip（透明裁剪）的树叶、草地、栅栏等材质，还可能需要采样纹理并执行裁剪逻辑。

因此，阴影 Pass 不一定完全没有像素着色成本。

### 11.2 阴影采样阶段的开销

正式渲染场景时，需要根据像素位置访问 Shadow Map，并判断是否被遮挡。

如果每个像素只采样一次 Shadow Map，成本通常相对低。

但如果使用 PCF、PCSS 等软阴影方案：

每个像素可能需要多次深度比较，有时还需要额外的遮挡物搜索。

对于高分辨率画面、多个投影光源、大面积阴影接收物体，采样开销就会增加。

### 11.3 影响阴影性能的重要因素

|因素|对性能的影响|常见优化手段|
|---|---|---|
|投射阴影的光源数量|更多阴影图和采样|限制重要投影光源|
|投射阴影的物体数量|增加 Shadow Pass 几何开销|阴影剔除|
|阴影距离|扩大覆盖范围与物体集合|减小 Shadow Distance|
|Shadow Map 分辨率|增加存储、带宽与处理成本|按重要性分配|
|CSM 级联数量|增加阴影绘制与维护成本|合理控制级联|
|PCF / PCSS 采样数|增加像素阶段负担|动态降低采样|
|动态更新频率|增加 Shadow Map 重绘成本|静态或局部缓存|

还要区分一点：降低 Shadow Map 分辨率，通常能够减少带宽和光栅化相关开销，但如果瓶颈主要来自几何体顶点处理，那么仅降低分辨率不一定能带来明显收益。

## 十二、在 Unity 和 UE 中如何对应这些技术？

### 12.1 Unity

在 Unity 中，使用 URP 时常见的阴影相关功能包括主方向光实时阴影、附加光源阴影、Shadow Map Resolution、Shadow Distance、Shadow Cascades、Soft Shadows，以及与平台和管线设置相关的 Bias 参数。

如果自己编写 URP Shader，通常不需要从零实现 Shadow Map。

例如：

```
#include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Lighting.hlsl"

// 在顶点阶段获取世界空间位置
VertexPositionInputs posInputs =
    GetVertexPositionInputs(positionOS.xyz);

// 获取主光源 Shadow Map 的查询坐标
float4 shadowCoord =
    GetShadowCoord(posInputs);

// 在片元阶段查询主光源
Light mainLight = GetMainLight(shadowCoord);

// shadowAttenuation 是主光源的阴影可见度
// 1 表示没有被遮挡
// 0 表示完全遮挡
// 0~1 的值可表示过滤后的部分可见度
float shadowAttenuation =
    mainLight.shadowAttenuation;
```

实际使用时需要配合正确的 Shader Pass、顶点与片元阶段、阴影关键字变体，以及 URP 对应版本的阴影设置。

这段代码的意义是：

Unity 已经帮助开发者完成了 Shadow Map 的生成、光源矩阵计算、级联处理和阴影查询，我们只需要获取阴影衰减结果。

### 12.2 Unreal Engine 5

UE5 中，阴影功能通常由引擎渲染管线负责，开发者更多是通过项目渲染设置、光源属性和相关质量参数来控制。

常见的相关技术包括：

|技术|主要作用|
|---|---|
|Shadow Maps|传统动态阴影映射|
|Cascaded Shadow Maps|方向光阴影的距离分级|
|Virtual Shadow Maps|高精度虚拟化阴影|
|Distance Field Shadows|利用距离场表示进行阴影计算|
|Contact Shadows|提供局部的屏幕空间接触阴影细节|
|Ray-Traced Shadows|通过射线追踪判断光线遮挡|

其中 Contact Shadows（接触阴影）常用来补充小型物体与地面之间的精细遮挡。

因为即使使用高分辨率 Shadow Map，也可能无法稳定表现非常细小的缝隙与接触细节。

屏幕空间接触阴影可通过当前画面的深度信息沿光照方向进行短距离追踪，估算局部遮挡。

但它只能利用屏幕空间中可获得的信息，存在屏幕边缘、不可见遮挡物等限制。

UE5 的这些阴影方案可以组合使用，但具体支持关系取决于引擎版本、渲染路径与项目配置。例如虚拟阴影贴图与传统阴影贴图不是简单同时对同一光源无条件叠加。

# 十三、实际商业项目如何选择阴影方案？

以多人角色场景和大型 3D 动作游戏为例。

### 场景一：大量低精度角色

例如移动端游戏中，屏幕内存在大量 NPC、小怪，角色阴影只用于表示脚底接触位置。

这种情况可以优先使用：

Blob Shadow + 简单地面检测。

原因是每个 NPC 都独立使用高精度动态 Shadow Map 未必划算，尤其是角色数量很多的时候。

### 场景二：中低端设备上的人物轮廓阴影

如果希望保留真实人物轮廓，但是场景地面相对简单，可以考虑：

Planar Shadow + Stencil 控制 + 合理的透明度。

这种方案可以用相对简单的顶点变换，获得比圆片阴影更准确的几何轮廓。

但是不适合以复杂地形和全场景真实阴影为主要卖点的场景。

### 场景三：第三人称动作游戏

如果需要角色动态阴影、场景遮挡、自阴影，以及角色与场景之间完整的光照关系，那么更适合：

Shadow Mapping + CSM + PCF。

这是一个相对成熟的传统实时阴影组合。

可以通过不同级联控制世界空间分辨率，再使用 PCF 改善边缘效果。

### 场景四：类似《鸣潮》的高精度 3D 动作游戏

对于大量动态角色、复杂地形、动态天气和高精度美术资产的场景，可以考虑更加复杂的组合：

# 十四、总结：这些技术到底解决了什么问题？

|技术|最主要解决的问题|
|---|---|
|Blob Shadow|用极低成本模拟角色脚底阴影|
|Planar Shadow|用几何投影保留模型轮廓|
|Shadow Mapping|判断光源与表面之间的真实可见遮挡|
|Depth Bias|减少 Shadow Acne|
|Normal Bias|辅助减少自阴影伪影|
|PCF|改善 Shadow Map 阴影边缘锯齿|
|PCSS|近似面积光源的距离相关软阴影|
|CSM|改善大范围方向光阴影的精度分配|
|Variance Shadow Maps|利用深度矩信息实现可过滤阴影|
|Virtual Shadow Maps|用虚拟分页管理高分辨率阴影|
|Contact Shadows|补充局部接触位置的阴影细节|

在学习和面试中，我认为最应该掌握的不是单纯记忆这些技术名称，而是理解下面几组关系：

第一组：圆片阴影、平面阴影、Shadow Map。 三者分别通过贴图模拟、几何投影和深度可见性比较生成阴影。

第二组：Shadow Map、PCF、PCSS。 Shadow Map 负责基础遮挡判断，PCF 负责阴影过滤，PCSS 进一步估算距离相关的半影宽度。

第三组：Shadow Map、CSM、Virtual Shadow Maps。 它们分别对应基础深度阴影、按相机距离分配阴影精度，以及高分辨率阴影的虚拟化管理。

第四组：Shadow Acne 与 Peter Panning。 前者通常与深度精度和偏移不足有关，后者通常与过大的偏移有关，两者是 Shadow Mapping 中非常经典的一对问题。

如果要从底层渲染原理真正掌握阴影系统，最值得动手实现的是一个支持方向光的基础 Shadow Mapping，然后依次添加 Bias、3×3 PCF、CSM 和 PCSS。完整走过这条路线后，再去理解 UE5 的 Virtual Shadow Maps，会容易得多。
