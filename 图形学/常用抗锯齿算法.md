游戏渲染里常见的抗锯齿（Anti-Aliasing，AA）算法，核心目的都是解决**离散像素采样不足导致的锯齿、闪烁、摩尔纹等走样（Aliasing）问题**。

可以先把常用方法按思路分成几类：

```
抗锯齿 Anti-Aliasing
│
├─ 空间采样类
│   ├─ SSAA / Supersampling
│   └─ MSAA / Multisampling
│
├─ 后处理类
│   ├─ FXAA
│   └─ SMAA
│
├─ 时间域类
│   ├─ TAA
│   ├─ TAAU
│   └─ TSR
│
└─ AI / 重建类
    ├─ DLAA
    ├─ DLSS
    ├─ FSR
    └─ XeSS
```

其中游戏开发和面试里最重要的通常是：

**SSAA → MSAA → FXAA → SMAA → TAA → TAAU / TSR**。

---

# 一、为什么会产生锯齿？

假设屏幕上有一条斜线：

```
真实世界中的理想线：

        /
       /
      /
     /
    /
```

但是屏幕由离散像素组成：

```
[] [] [] []
   []
   []
      []
      []
         []
```

GPU最终必须回答一个问题：

> 这个像素到底属于三角形，还是不属于三角形？

最简单的光栅化通常会使用某个采样点判断覆盖情况。

例如一个像素：

```
┌─────────┐
│         │
│    ●    │   ← Pixel Center 像素中心
│         │
└─────────┘
```

如果三角形覆盖中心：

```
Inside → 绘制
```

否则：

```
Outside → 不绘制
```

所以原本连续的几何边缘，就会变成：

```
████
   ████
      ████
         ████
```

于是产生明显的阶梯。

这就是：

> **Spatial Aliasing（空间走样）**

---

# 二、Aliasing 本质是什么？

从信号处理角度理解非常重要。

游戏里的图像可以看成一个连续信号：

```
连续场景
   ↓
Rasterization 光栅化
   ↓
Sampling 采样
   ↓
Pixel 像素
```

但是屏幕分辨率有限。

例如：

```
真实信号：

~~~~\/\/\/\/\/\/~~~~

采样点：

●        ●        ●
```

如果信号变化频率太高，而采样频率不足，就会产生错误结果。

根据 Nyquist Sampling Theorem：

```
采样频率 >= 信号最高频率 × 2
```

否则就可能出现走样。

游戏中的典型表现包括：

```
几何边缘
   ↓
锯齿

远处纹理
   ↓
摩尔纹

细小物体
   ↓
闪烁

高光
   ↓
Specular Shimmering
高光闪烁
```

所以：

> 抗锯齿的本质就是提高采样质量，或者估算“真实像素覆盖结果”。

---

# 三、SSAA —— 超级采样抗锯齿

全称：

> **Super-Sampling Anti-Aliasing**

SSAA可以理解为最暴力、最正确，同时也是最昂贵的一种方案。

---

## 1. SSAA原理

假设最终分辨率：

```
1920 × 1080
```

如果使用：

```
2× SSAA
```

一种典型做法是按更高分辨率渲染：

```
3840 × 2160
```

然后：

```
高分辨率图像
      ↓
Down Sample
下采样
      ↓
1920 × 1080
```

也就是：

```
一个最终Pixel

┌────┬────┐
│ S0 │ S1 │
├────┼────┤
│ S2 │ S3 │
└────┴────┘

最终颜色：

Color =
(C0 + C1 + C2 + C3) / 4
```

相当于每个像素真正计算多个子像素。

---

# 四、SSAA为什么效果最好？

假设三角形只覆盖一个Pixel的25%。

不抗锯齿：

```
100% 黑
或
100% 白
```

SSAA可能得到：

```
25%覆盖

最终颜色：

0.25 × TriangleColor
+
0.75 × BackgroundColor
```

于是边缘就变成渐变：

```
████████
████▓▒░
      ░▒▓████
```

视觉上自然很多。

---

# 五、SSAA解决哪些问题？

SSAA最大的优势：

> 它不是只处理几何边缘。

因为整个Shader都以高分辨率执行。

所以它可以改善：

```
几何边缘锯齿
✔

纹理锯齿
✔

Shader锯齿
✔

Specular高光闪烁
✔

Alpha Test植被
✔

细线
✔
```

这是MSAA很难做到的。

---

# 六、SSAA最大缺点

性能非常昂贵。

假设：

```
1920 × 1080

≈ 2.07 million pixels
```

如果每个维度放大2倍：

```
3840 × 2160

≈ 8.29 million pixels
```

像素数量：

```
4倍
```

那么：

```
Pixel Shader
Texture Sampling
Lighting
Bandwidth
RenderTarget
```

都会大幅增加。

所以现代实时游戏通常不会直接使用SSAA。

---

# 七、SSAA总结

```
优点：

✔ 质量非常高
✔ 原理简单
✔ 几乎所有类型的Aliasing都能改善
✔ 不依赖Temporal History

缺点：

✘ 性能消耗巨大
✘ FillRate压力大
✘ Shader计算量大
✘ 显存带宽压力大
```

---

# 八、MSAA —— 多重采样抗锯齿

全称：

> **Multi-Sample Anti-Aliasing**

MSAA可以理解成：

> SSAA的优化版本。

核心思想：

**Coverage多次采样，但Shader不一定执行多次。**

这是理解MSAA最重要的一句话。

---

# 九、MSAA的基本原理

例如：

```
4× MSAA
```

每个Pixel里面放4个Coverage Sample：

```
┌────────────┐
│  ●      ●  │
│            │
│  ●      ●  │
└────────────┘
```

假设三角形覆盖了两个：

```
┌────────────┐
│  ●██████●  │
│ █████      │
│ ●██     ○  │
└────────────┘

覆盖率：

2 / 4 = 50%
```

最终：

```
50% TriangleColor
+
50% BackgroundColor
```

于是边缘自然平滑。

---

# 十、MSAA和SSAA最大的区别

这是面试高频。

### SSAA

例如4× SSAA：

```
4个Sample
↓
4次Pixel Shader
↓
4个颜色
↓
平均
```

可以理解成：

```
Coverage ×4
Shader ×4
Color ×4
```

---

### MSAA

例如4× MSAA：

```
4个Coverage Sample

但是通常：

Pixel Shader
只对Primitive执行较少次数
```

然后结果共享给属于同一个Primitive的Samples。

所以：

```
Coverage ×4

Pixel Shader
≈ 1次
```

这就比SSAA便宜很多。

---

# 十一、MSAA的关键：Coverage Sample

MSAA主要提高：

```
Triangle Coverage
```

也就是：

> 三角形到底覆盖这个Pixel多少？

例如：

```
Pixel

┌─────────────┐
│ ●        ●  │
│██████       │
│████████ ●   │
│ ●██████████ │
└─────────────┘
```

如果：

```
3 / 4 Samples
```

被覆盖：

```
Coverage = 75%
```

于是最终颜色：

```
75% TriangleColor
+
25% BackgroundColor
```

---

# 十二、MSAA解决不了什么？

这是MSAA最大的局限。

MSAA主要解决：

> **Polygon Edge / Geometry Edge**

即：

```
三角形边缘
```

但假如一个完整三角形内部：

```
██████████
██████████
██████████
```

Shader输出本身有剧烈变化：

```
黑白黑白黑白
```

MSAA一般无能为力。

例如：

### 1. Alpha Test植被

```
一张Quad
+ 树叶Alpha纹理
```

几何边界实际上是：

```
┌──────────┐
│   🌿     │
│ 🌿🌿🌿   │
│   🌿     │
└──────────┘
```

但GPU几何边缘仍然只是：

```
┌──────────┐
│          │
│          │
│          │
└──────────┘
```

叶片边缘来自：

```
Alpha Test / Clip
```

而不是Triangle Edge。

所以传统MSAA改善有限。

---

# 十三、MSAA与延迟渲染

这是一个非常经典的问题。

Deferred Rendering：

```
Geometry Pass

        ↓

GBuffer

BaseColor
Normal
Roughness
Metallic
Depth

        ↓

Lighting Pass
```

如果开启4× MSAA：

```
每个GBuffer
可能需要多个Sample
```

例如原来：

```
Normal:

1 Pixel
=
1 Normal
```

MSAA以后：

```
1 Pixel
=
4 Samples
=
最多4个Normal
```

GBuffer内存和带宽会显著增加。

因此：

> **MSAA更适合Forward Rendering。**

Forward：

```
Triangle
↓
Lighting
↓
Framebuffer
```

处理起来相对自然。

这也是现代Deferred游戏很少依赖传统MSAA的原因之一。

---

# 十四、FXAA —— 快速近似抗锯齿

全称：

> **Fast Approximate Anti-Aliasing**

FXAA与MSAA思路完全不同。

它属于：

> **Post Processing Anti-Aliasing**

也就是说：

```
整个场景已经渲染完
        ↓
拿到最终Color Buffer
        ↓
FXAA Shader
        ↓
寻找锯齿
        ↓
模糊/平滑边缘
```

---

# 十五、FXAA工作原理

它不关心：

```
Triangle
Depth
Normal
Coverage
```

只看最终颜色。

例如：

```
██████
    ██████
        ██████
```

FXAA发现这里：

```
亮度差非常大
```

即：

```
Luminance Gradient
亮度梯度
```

于是认为：

```
这里可能是Edge
```

接着沿边缘方向取样：

```
↖ ↑ ↗
← ● →
↙ ↓ ↘
```

估计边缘方向：

```
────────
```

或者：

```
/
```

然后进行一些混合：

```
Color =
Neighbor Samples Weighted Average
```

从而让边缘平滑。

---

# 十六、FXAA为什么快？

因为它：

```
不增加Geometry采样
不增加Rasterizer采样
不增加GBuffer
不需要History
```

本质上只是：

```
一次Fullscreen Pass
```

例如：

```
Render Image
    ↓
Fullscreen Quad
    ↓
FXAA Shader
```

所以非常便宜。

---

# 十七、FXAA缺点：糊

因为FXAA只是看到：

```
Color Edge
```

它并不知道：

```
这是锯齿？
还是正常纹理细节？
还是UI文字？
```

例如：

```
文字：

ABCDE
```

FXAA可能认为：

```
A边缘
B边缘
C边缘

都是需要平滑的Edge
```

于是：

```
锐利文字
↓
略微模糊
```

所以FXAA经典缺点：

> **Image Blur**

---

# 十八、FXAA总结

```
优点：

✔ 非常快
✔ 实现简单
✔ 几乎任何渲染管线都能使用
✔ Deferred友好
✔ Alpha Test边缘也能处理

缺点：

✘ 图像偏糊
✘ 细节丢失
✘ Temporal Aliasing处理能力弱
✘ 远处细节仍可能闪烁
```

---

# 十九、SMAA —— 亚像素形态抗锯齿

全称：

> **Subpixel Morphological Anti-Aliasing**

可以把SMAA理解成：

> **高级版FXAA。**

两者都属于：

```
Post Process AA
```

但SMAA对边缘做了更加复杂的分析。

---

# 二十、SMAA大致流程

通常分几个Pass：

```
Pass 1
Edge Detection
边缘检测

↓

Pass 2
Pattern Search
搜索边缘形状

↓

Pass 3
Blend Weight Calculation
计算混合权重

↓

Pass 4
Neighborhood Blending
邻域混合
```

例如检测：

```
█████
    █
    █
    █
```

SMAA会尝试识别：

```
L型边缘
T型边缘
斜线
长边
```

然后使用预计算模式：

```
Area Texture
Search Texture
```

获得更合理的混合权重。

---

# 二十一、SMAA vs FXAA

一般来说：

|项目|FXAA|SMAA|
|---|---|---|
|性能|⭐⭐⭐⭐⭐|⭐⭐⭐⭐|
|清晰度|⭐⭐|⭐⭐⭐⭐|
|几何边缘|好|很好|
|细线|一般|较好|
|模糊程度|较明显|较低|
|Temporal稳定性|较差|较差|
|实现复杂度|低|较高|

所以过去经常可以看到：

```
FXAA

低配方案
```

和：

```
SMAA

高质量Post AA
```

---

# 二十二、为什么后来TAA成为主流？

现代游戏最大的抗锯齿问题其实不是静态图：

```
静态：

█████
   █████
      █████
```

而是相机运动以后：

```
Frame 1
  |

Frame 2
   |

Frame 3
    |

Frame 4
   |
```

细小物体可能：

```
出现
消失
出现
消失
```

形成：

> **Temporal Aliasing（时间走样）**

肉眼看到就是：

```
Shimmering
闪烁

Crawling
边缘爬动

Flickering
频闪
```

FXAA和普通SMAA只有：

```
当前Frame
```

完全不知道：

```
上一Frame
```

所以难以解决Temporal Aliasing。

---

# 二十三、TAA —— 时间抗锯齿

全称：

> **Temporal Anti-Aliasing**

这是现代3A游戏中最重要的AA之一。

核心思想：

> **利用多个Frame的Sample共同重建当前Pixel。**

简单理解：

```
Frame N-3 ─┐
Frame N-2 ─┤
Frame N-1 ─┼→ 当前Frame
Frame N   ─┘
```

而不是只看：

```
当前Frame
```

---

# 二十四、TAA为什么需要Jitter？

这是理解TAA最关键的地方之一。

正常情况下每帧Pixel Sample在：

```
┌─────────┐
│         │
│    ●    │
│         │
└─────────┘
```

如果所有Frame都采相同位置：

```
Frame1 ●
Frame2 ●
Frame3 ●
Frame4 ●
```

那积累100帧也没有意义。

所以TAA会对：

> Projection Matrix

加入微小偏移：

```
Jitter
抖动
```

例如：

```
Frame1

●

Frame2

      ●

Frame3

   ●

Frame4

        ●
```

等于不同帧采Pixel的不同Subpixel位置。

长期积累以后：

```
┌────────────┐
│ ●      ●   │
│            │
│    ●       │
│        ●   │
└────────────┘
```

类似：

```
Temporal Super Sampling
时间超级采样
```

---

# 二十五、TAA基本流程

可以简单画成：

```
Current Frame
当前帧
        │
        ├──────────┐
        │          │
        ↓          │
Motion Vector      │
运动矢量            │
        ↓          │
Reprojection       │
历史重投影           │
        ↓          │
Previous History ←─┘
历史颜色
        │
        ↓
History Validation
历史有效性判断
        │
        ↓
Neighborhood Clamp
邻域限制
        │
        ↓
Temporal Blend
时间混合
        │
        ↓
New History
```

---

# 二十六、Motion Vector为什么重要？

假设一个物体：

```
上一帧：

   ●
```

移动到了：

```
当前帧：

       ●
```

如果直接混合：

```
Previous Color
+
Current Color
```

就会得到：

```
   ●   ●
```

也就是：

> Ghosting（鬼影）

因此需要：

```
Motion Vector
速度缓冲
```

告诉GPU：

```
Current Pixel

上一帧对应的位置在哪里？
```

例如：

```
Current UV
    ↓
Motion Vector
    ↓
Previous UV
```

典型表示：

```
PreviousUV =
CurrentUV + Velocity
```

或者根据具体引擎定义：

```
PreviousUV =
CurrentUV - Velocity
```

---

# 二十七、Reprojection —— 历史重投影

当前像素：

```
Current Pixel
P
```

通过：

```
Motion Vector
```

找到：

```
上一Frame的P
```

于是：

```
HistoryColor =
HistoryTexture.Sample(PreviousUV)
```

然后：

```
FinalColor =
CurrentColor * α
+
HistoryColor * (1 - α)
```

例如：

```
Current = 10%
History = 90%
```

优势：

```
画面稳定
噪声小
锯齿少
```

但问题也来了：

```
历史权重过大

→ Ghosting
→ 拖影
→ 模糊
```

---

# 二十八、TAA最大问题：Ghosting

例如角色快速移动：

```
Frame1:

●

Frame2:

   ●

Frame3:

      ●
```

历史错误累积以后：

```
● ░ ● ░ ●
```

看起来像：

```
拖着一条残影
```

这就是：

> Temporal Ghosting

---

# 二十九、为什么TAA容易糊？

因为本质上：

```
Current Frame
+
Previous Frame
+
Previous Previous Frame
...
```

不断做时间滤波。

相当于：

> 低通滤波

所以高频细节容易被过滤。

结果：

```
TAA Off

非常锐利
但闪烁明显

TAA On

稳定
但偏软
```

因此现代游戏经常额外使用：

```
Sharpen
锐化
```

补偿TAA模糊。

---

# 三十、Neighborhood Clamp —— TAA的重要技术

假设当前Pixel附近颜色：

```
0.4
0.5
0.6
```

那么可以认为合理历史范围大约：

```
Min = 0.4
Max = 0.6
```

但是History：

```
1.0
```

显然可能来自：

```
错误重投影
```

于是：

```
History =
Clamp(History, Min, Max)
```

变为：

```
0.6
```

这就叫：

> **History Clamping / Neighborhood Clamping**

用于减少：

```
Ghosting
历史污染
```

# 三十一、TAA优缺点

```
优点：

✔ Temporal稳定性非常强
✔ 减少远处闪烁
✔ 减少细线闪烁
✔ 减少Specular Shimmering
✔ 对Deferred Rendering友好
✔ 性价比很高

缺点：

✘ 容易模糊
✘ 容易Ghosting
✘ 快速运动容易出现残影

✘ 算法复杂
```

# 三十二、Disocclusion —— TAA经典难题

假设：

```
Frame 1：

AAAAABBBBB
```

A物体挡住B。

然后A移动：

```
Frame 2：

AAABBBBBBB
```

这里新出现的：

```
BB
```

上一帧根本没有对应的B信息。

这叫：

> **Disocclusion**  
> 遮挡解除 / 新暴露区域

这时TAA不能可靠地使用History。

否则就会产生：

```
Ghosting
黑边
拖影
错误颜色
```

所以现代TAA会根据：

```
Depth
Normal
Motion Vector
Object ID
Neighborhood
```

判断：

```
History是否可信
```

# 三十三、TAAU —— 时间升采样

全称：

> **Temporal Anti-Aliasing Upsampling**

思路：

```
低分辨率渲染

例如：
1280 × 720

↓

Temporal Samples
时间积累

↓

重建

↓

1920 × 1080
```

所以TAA不仅：

```
Anti-Aliasing
```

还承担：

```
Upsampling / Reconstruction
```

# 四十七、特别容易混淆的一点：Fragment和Sample

例如：

```
4x MSAA
```

不要直接理解成：

> 一个Pixel一定运行4次Pixel Shader。

更准确地说：

```
一个Pixel
↓
拥有4个Coverage Samples
```

Rasterizer判断：

```
Sample0 Covered?
Sample1 Covered?
Sample2 Covered?
Sample3 Covered?
```

但Shader执行次数取决于：

```
Primitive Coverage
Sample Frequency Shading
GPU实现
Shader状态
```

传统意义下MSAA的优化核心正是：

> **增加Coverage采样，而不是像SSAA一样无脑增加全部Shader采样。**

这是MSAA和SSAA本质区别。

# 四十九、面试最常见问题

你如果是为了UE / Unity图形面试，这几个尤其建议掌握。

### Q1：MSAA和SSAA区别是什么？

答：

```
SSAA：
真正提高整个场景采样率，
Shader、纹理、Coverage等都会增加采样。

MSAA：
主要增加几何Coverage Sample，
通常共享Pixel Shader计算结果。

因此MSAA性能远好于SSAA，
但主要只能处理几何边缘Aliasing。
```

---

### Q2：为什么MSAA不能很好解决Alpha Test？

因为：

```
MSAA判断的是Triangle Coverage
```

而：

```
Alpha Test边缘
```

是在：

```
Pixel Shader
```

里面通过：

```
clip(alpha - threshold);
```

产生的。

它不是：

```
真实Triangle Edge
```

所以普通MSAA不知道这个边缘。

可以用：

```
Alpha To Coverage
```

改善。

---

### Q3：FXAA为什么模糊？

因为FXAA只看最终：

```
Color Buffer
```

不知道一个Edge到底是：

```
Geometry Edge

还是

Texture Detail
```

因此可能把真实高频细节一起Smooth掉。

---

### Q4：TAA为什么会Ghosting？

因为：

```
Current Frame
+
History Frame
```

混合。

如果：

```
Motion Vector错误

或

遮挡关系变化

或

History无效
```

历史颜色就会污染当前Frame。

---

### Q5：为什么TAA要Jitter？

为了：

```
不同Frame采不同Subpixel位置
```

从而利用多帧积累增加有效Sampling Rate。

---

### Q6：为什么Deferred不喜欢MSAA？

因为：

```
每个GBuffer都可能需要Multi-Sample
```

导致：

```
Memory ↑
Bandwidth ↑
Resolve Complexity ↑
Lighting Complexity ↑
```
