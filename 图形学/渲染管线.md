实时渲染管线拆成了三大核心阶段：

> **Application Stage 应用程序阶段 → Geometry Stage 几何阶段 → Rasterizer Stage 光栅化阶段**

可以先记住整条主线：

```
CPU准备场景
    ↓
Application Stage
应用程序阶段
    ↓
提交顶点、材质、纹理、相机等数据
    ↓
Geometry Stage
几何阶段
    ↓
把3D三角形变换成屏幕空间三角形
    ↓
Rasterizer Stage
光栅化阶段
    ↓
判断三角形覆盖哪些像素，并计算像素颜色
    ↓
Framebuffer / Render Target
    ↓
最终图像
```

你图里的章节基本就是围绕这条流程展开的。

---

# 1. Architecture：整体架构

先理解一个最核心的分工：

```
CPU                         GPU
 │                           │
 │ Application Stage         │
 │ 场景、逻辑、剔除、提交     │
 │                           │
 └────── Draw Call ─────────→│
                             │
                     Geometry Stage
                             │
                     Rasterizer Stage
                             │
                             ↓
                         Render Target
```

也就是说，一帧画面并不是 GPU 自己凭空生成的。

CPU 要先告诉 GPU：

> 画什么、用什么模型、什么材质、什么相机、什么纹理、什么 Shader。

然后 GPU 才负责大量并行计算。

在游戏引擎里可以粗略理解成：

```
游戏世界
 ↓
CPU决定画什么
 ↓
GPU决定怎么把它画出来
```

---

# 2.2 Application Stage

# 应用程序阶段

Application Stage 一般主要运行在 **CPU** 上。

它处理的是：

> “这一帧，我到底需要渲染什么？”

比如场景里：

```
Player
Enemy × 100
Tree × 500
Building × 200
Light × 20
```

CPU 不会什么都直接扔给 GPU。

它通常会先处理：

```
游戏逻辑
动画
物理
摄像机
LOD
场景管理
视锥剔除
遮挡剔除
排序
批处理
Draw Call准备
```

例如场景有 10000 个物体：

```
10000 Objects
      ↓
Frustum Culling
      ↓
3000
      ↓
Occlusion Culling
      ↓
1500
      ↓
LOD / Batching
      ↓
提交GPU
```

所以 Application Stage 的最终目标可以简单理解为：

> **整理出这一帧 GPU 真正需要处理的数据。**

然后通过类似：

```
DrawIndexed(...)
```

这样的 Draw Call 把工作提交给 GPU。

---

# 3. Geometry Stage

# 几何阶段

这部分是图形学最重要的基础之一。

Geometry Stage 要解决的问题是：

> 一个模型里的 3D 顶点，到底怎么跑到屏幕上的？

你图里拆成了：

```
2.3.1 Model and View Transform
2.3.2 Vertex Shading
2.3.3 Projection
2.3.4 Clipping
2.3.5 Screen Mapping
```

把它们串起来：

```
Local Space
模型空间
    ↓
Model Transform
    ↓
World Space
世界空间
    ↓
View Transform
    ↓
View Space
观察空间
    ↓
Vertex Shading
    ↓
Projection
    ↓
Clip Space
裁剪空间
    ↓
Clipping
    ↓
Perspective Divide
    ↓
NDC
    ↓
Screen Mapping
    ↓
Screen Space
屏幕空间
```

这条链一定要熟。

---

# 3.1 Model and View Transform

# 模型和观察变换

假设美术制作了一个角色。

角色模型里的一个顶点可能是：

\[ P=(1,2,0) \]

这个坐标不是世界坐标，而是：

> Model Space / Local Space  
> 模型空间 / 局部空间

例如角色脚底可能就是：

```
(0,0,0)
```

不管角色最终放到游戏地图哪里，它自己模型里的坐标不变。

---

## Model Transform

通过 Model Matrix：

\[ P_{world}=M P_{local} \]

把模型空间转换成：

> World Space 世界空间

例如：

```
模型内部：
(0,0,0)

角色放到：
(100,200,0)
```

那么 Model Matrix 中就包含：

```
Translation
Rotation
Scale
```

即：

```
平移
旋转
缩放
```

---

## View Transform

然后：

```
World Space
     ↓
View Matrix
     ↓
View Space
```

View Space 也叫：

```
Camera Space
Eye Space
观察空间
摄像机空间
```

它的核心思想是：

> 把整个世界转换到以摄像机为参考系的坐标中。

数学上通常：

\[ V=CameraTransform^{-1} \]

所以如果摄像机：

```
向右移动10
```

从数学角度看，相当于：

```
整个世界向左移动10
```

---

# 3.2 Vertex Shading

# 顶点着色

接下来执行：

> Vertex Shader 顶点着色器

GPU 会对每个顶点执行一次。

比如模型有：

```
100000 vertices
```

就会启动大量 Vertex Shader Invocation。

最基本的 Vertex Shader：

```
Output VS(Input v)
{
    Output o;
    o.Position = MVP * v.Position;
    return o;
}
```

但 Vertex Shader 不只是处理 Position。

输入通常有：

```
Position
Normal
Tangent
UV
Vertex Color
Bone Weight
Bone Index
```

它可能做：

```
顶点坐标变换
骨骼蒙皮
顶点动画
法线变换
UV传递
```

例如角色骨骼动画，本质上很大一部分工作就是：

```
原始顶点
   ↓
Bone Matrix
   ↓
动画后的顶点
```

---

# 3.3 Projection

# 投影

现在顶点已经到了：

```
View Space
```

下一步是：

> 把 3D 世界投影到一个 2D 屏幕。

这就是 Projection。

最常见的是：

## Perspective Projection

透视投影

特点：

> 近大远小。

例如：

```
Camera
  |
  |        大箱子
  |       ██████
  |
  |                    同样大小的箱子
  |                         ██
```

实际大小一样，但远处在屏幕上更小。

通过：

\[ P_{clip}=P_{projection}P_{view} \]

得到：

```
Clip Space
```

最终完整变换通常写：

\[ P_{clip} = P V M P_{local} \]

或者：

\[ P_{clip}=MVP P_{local} \]

取决于矩阵和向量的书写约定。

---

# 为什么投影以后是 x,y,z,w？

因为此时使用：

> Homogeneous Coordinates  
> 齐次坐标

所以：

\[ (x,y,z) \]

会变成：

\[ (x,y,z,w) \]

这个 `w` 非常重要。

因为之后要执行：

\[ x_{ndc}=\frac{x}{w} \]\[ y_{ndc}=\frac{y}{w} \]\[ z_{ndc}=\frac{z}{w} \]

这就是：

> Perspective Divide  
> 透视除法。

近大远小很大程度上就是在这个过程中体现出来的。

---

# 3.4 Clipping

# 裁剪

投影完成后，并不是所有三角形都应该进入下一阶段。

例如：

```
             三角形
              /\
      ┌──────/─│────┐
      │     /  │    │
      │    /___│    │
      │             │
      └─────────────┘
        可视区域
```

一部分三角形跑到视野外了。

GPU 要进行：

> Clipping 裁剪

例如一个三角形：

```
一个顶点在屏幕里
两个顶点在屏幕外
```

不能简单整个丢掉，因为它仍然有一部分可见。

于是 GPU 会：

```
原三角形
   ↓
和裁剪平面求交
   ↓
生成新的顶点
   ↓
得到新的三角形
```

典型裁剪范围对应：

```
Left
Right
Top
Bottom
Near
Far
```

即视锥体的几个平面。

---

# 3.5 Screen Mapping

# 屏幕映射

裁剪以后，会执行 Perspective Divide：

```
Clip Space
     ↓
÷ w
     ↓
NDC
```

NDC：

> Normalized Device Coordinates  
> 标准化设备坐标

例如 x、y 通常被规范到：

\[ [-1,1] \]

可以理解成：

```
        y = 1
          ↑
          |
x=-1 -----+----- x=1
          |
          ↓
        y=-1
```

但是显示器不是：

```
-1 ～ 1
```

显示器可能是：

```
2560 × 1440
```

于是需要：

> Screen Mapping / Viewport Transform

把：

```
NDC (-1, 1)
```

映射到：

```
Pixel (0, 2560)

Pixel (0, 1440)
```

例如：

```
NDC (0,0)
```

通常大约就是：

```
屏幕中心
(1280,720)
```

至此：

> 3D 顶点终于变成了屏幕上的顶点。

---

# Geometry Stage 到这里完成了什么？

举个最直观的例子。

最开始是：

```
3D模型：

      V0
      /\
     /  \
    /    \
   V1----V2
```

经过：

```
Model
View
Projection
Clipping
Screen Mapping
```

最后得到：

```
屏幕：

             V0'
             /\
            /  \
           /    \
          V1'---V2'
```

Geometry Stage 最终并没有真正给每个像素上色。

它只解决：

> **三角形在屏幕什么地方。**

接下来才轮到 Rasterizer Stage。

---

# 4. Rasterizer Stage

# 光栅化阶段

图中这一部分拆成：

```
2.4.1 Triangle Setup
2.4.2 Triangle Traversal
2.4.3 Pixel Shading
2.4.4 Merging
```

整体目标：

> 把屏幕空间中的三角形转换成最终 Pixel。

即：

```
Triangle
    ↓
Rasterization
    ↓
Fragment
    ↓
Pixel Shader
    ↓
Depth / Stencil / Blend
    ↓
Pixel
```

---

# 4.1 Triangle Setup

# 三角形设置

现在 GPU 已经知道：

```
V0 = (100,100)
V1 = (500,200)
V2 = (300,600)
```

GPU 首先要根据三个顶点建立三角形的信息。

例如需要计算：

```
三条边
面积
朝向
边方程
Bounding Box
```

其中会涉及一个经典判断：

```
这个三角形是正面还是背面？
```

从而实现：

> Back Face Culling  
> 背面剔除

例如：

```
Counter-Clockwise
```

定义为正面：

```
A → B → C
```

如果顶点顺序反了：

```
A → C → B
```

可能就被认为是背面。

如果开启：

```
Backface Culling
```

则直接不继续处理。

---

# 4.2 Triangle Traversal

# 三角形遍历

这一步真正开始回答：

> 哪些 Pixel 被这个三角形覆盖？

例如：

```
           /\
          /██\
         /████\
        /██████\
       /████████\
```

GPU 会遍历三角形覆盖区域中的采样点。

比如：

```
Pixel A：三角形外
→ 不处理

Pixel B：三角形内
→ 生成Fragment
```

所以这一步就是通常说的：

> Rasterization 光栅化

更精确地说：

```
Triangle
↓
Samples / Fragments
```

---

# 插值也在这里非常重要

每个顶点都有：

```
V0:
UV = (0,0)

V1:
UV = (1,0)

V2:
UV = (0,1)
```

但是三角形内部这个点：

```
        V2
        /\
       / P\
      /    \
     /______\
   V0       V1
```

P 的 UV 是多少？

必须插值。

通常基于：

> Barycentric Coordinates  
> 重心坐标

表示为：

\[ P = \alpha V_0 + \beta V_1 + \gamma V_2 \]

其中：

\[ \alpha+\beta+\gamma=1 \]

于是可以插值：

```
UV
Normal
Vertex Color
World Position
Tangent
```

等等。

比如：

```
V0 Color = Red
V1 Color = Green
V2 Color = Blue
```

三角形内部就会得到渐变颜色。

---

# 4.3 Pixel Shading

# 像素着色

接下来进入：

> Pixel Shader / Fragment Shader

这一步回答：

> 这个 Fragment 最终应该是什么颜色？

例如非常简单：

```
return float4(1,0,0,1);
```

就是：

```
红色
```

但是真实游戏会复杂很多。

输入可能有：

```
UV
Normal
World Position
View Direction
Vertex Color
Tangent
```

然后进行：

```
Texture Sampling
Normal Mapping
Lighting
PBR
Shadow
Reflection
AO
```

例如：

```
UV
 ↓
Sample BaseColor Texture
 ↓
BaseColor
 ↓
PBR Lighting
 ↓
Shadow
 ↓
Final Color
```

所以 Pixel Shader 通常也是现代游戏 GPU 性能消耗非常大的地方。

---

# 举个简单光照例子

表面法线：

\[ N \]

光方向：

\[ L \]

最基本 Lambert：

\[ Diffuse=\max(N\cdot L,0) \]

如果：

```
N ↑
L ↑
```

则：

\[ N\cdot L=1 \]

很亮。

如果：

```
N ↑

L →
```

夹角 90°：

\[ N\cdot L=0 \]

直接光照为 0。

现代 UE 的 PBR 比这个复杂得多，但最底层仍然离不开这些向量计算。

---

# 4.4 Merging

# 合并

Pixel Shader 算出来：

```
“这个Fragment是红色”
```

还不代表它一定会出现在屏幕上。

因为可能：

```
它被另一个物体挡住了
```

或者：

```
它是透明的
```

所以进入：

> Merging 合并阶段

这里主要包括：

```
Depth Test
Stencil Test
Blending
```

---

# Depth Test

假设：

```
Camera
  ↓

A
██

      B
      ██
```

A 比 B 更近。

两个东西都映射到了同一个 Pixel。

假设 Depth Buffer 当前：

```
Depth = 0.2
```

B：

```
Depth = 0.8
```

Depth Test：

```
0.8 < 0.2 ?
```

失败。

所以 B：

```
被丢弃
```

这就是：

> Z-Buffer / Depth Buffer。

它解决：

> 谁挡住谁。

---

# Stencil Test

Stencil Buffer 可以理解为：

> 给每个 Pixel 再附加一个小整数标签。

例如：

```
Stencil = 1
```

然后设置：

```
只有Stencil == 1的Pixel才能渲染
```

常用于：

```
Outline
Portal
Mask
Mirror
特殊后处理
```

---

# Blending

例如当前屏幕已经是：

```
Blue
```

现在来一个 50% 透明的红色：

```
Red
Alpha = 0.5
```

常见混合公式：

\[ Final = Src\times\alpha + Dst\times(1-\alpha) \]

即：

```
Red × 0.5
+
Blue × 0.5
```

于是得到紫色附近的结果。

这就是：

> Alpha Blending。

---

# 5. 图中的 Through the Pipeline 是什么意思？

你图片里的：

> `2.5 Through the Pipeline`

一般就是拿一个实际三角形，从头到尾走一遍。

例如三个顶点：

```
Local Space

A = (-1,0,0)
B = ( 1,0,0)
C = ( 0,1,0)
```

### 第一步：Application

CPU：

```
这个三角形需要渲染
```

于是提交：

```
Vertex Buffer
Index Buffer
Material
Transform
Camera
```

---

### 第二步：Model Transform

```
Local
↓
World
```

比如整体移动到：

```
(0,0,10)
```

于是：

```
A = (-1,0,10)
B = ( 1,0,10)
C = ( 0,1,10)
```

---

### 第三步：View Transform

转换到 Camera Space。

如果 Camera 在原点：

```
基本没变化
```

---

### 第四步：Projection

进行透视投影：

```
3D position
↓
Clip Space
```

---

### 第五步：Clipping

判断：

```
是否超出视锥体
```

如果没有：

```
继续
```

---

### 第六步：Perspective Divide

```
x / w
y / w
z / w
```

得到 NDC。

---

### 第七步：Screen Mapping

例如变成：

```
A = (800,500)
B = (1100,500)
C = (950,300)
```

现在已经是屏幕空间三角形。

---

### 第八步：Triangle Setup

确定：

```
三条边
方向
Bounding Box
```

---

### 第九步：Triangle Traversal

假设覆盖：

```
30000个Pixel Sample
```

生成对应 Fragment。

---

### 第十步：Pixel Shader

每个 Fragment：

```
Sample Texture
↓
Normal
↓
Lighting
↓
PBR
↓
Color
```

得到类似：

```
RGBA = (0.8,0.2,0.1,1)
```

---

### 第十一步：Merging

检查：

```
Depth Test
Stencil Test
Blend
```

通过后写入：

```
Render Target
```

最终：

> 这个三角形出现在屏幕上。

---

# 最需要你掌握的是这两个分界

初学时很容易把所有阶段混在一起，我建议你牢牢记住：

### Geometry Stage 解决的是

> **三角形在哪里？**

即：

```
3D Vertex
    ↓
Screen Space Triangle
```

核心知识：

```
Matrix
Coordinate Space
Projection
Clipping
Perspective Divide
```

---

### Rasterizer Stage 解决的是

> **这个三角形覆盖哪些像素？这些像素是什么颜色？**

即：

```
Screen Triangle
      ↓
Fragments
      ↓
Pixel Color
```

核心知识：

```
Rasterization
Interpolation
Pixel Shader
Texture
Lighting
Depth
Stencil
Blending
```

所以整个章节其实可以极度压缩成一句：

> **Application Stage 决定“画什么”，Geometry Stage 决定“画在哪里”，Rasterizer Stage 决定“哪些像素被覆盖以及这些像素是什么颜色”。**

而你接下来学习这张图时，**最值得先详细攻克的是 `2.3 Geometry Stage`**，尤其是：

```
Local
 → World
 → View
 → Clip
 → NDC
 → Screen
```

因为只要这一段真正理解了，后面的 **光栅化、深度、阴影、屏幕空间效果、UE 的 View/Projection Matrix** 都会顺很多。
