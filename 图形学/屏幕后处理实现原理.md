- 它在渲染管线的什么位置
- 每种效果需要哪些 Buffer
- Shader 具体在做什么
- 常用数学原理
- 性能开销来自哪里
- 面试经常怎么问

---

# 一、什么是屏幕后处理

**屏幕后处理（Post Processing / Post Process）**，简单理解就是：

> 场景正常渲染完成后，不再直接操作模型，而是把已经渲染好的“屏幕图像”当成一张纹理，再进行二次加工。

例如场景正常渲染结果：

```
场景物体
  ↓
Vertex Shader
  ↓
Rasterization
  ↓
Pixel Shader
  ↓
HDR Scene Color
  ↓
========================
   屏幕后处理阶段
========================
  ↓
Bloom
  ↓
景深 DOF
  ↓
Motion Blur
  ↓
Tone Mapping
  ↓
Color Grading
  ↓
Vignette
  ↓
最终画面
```

典型代码思想就是：

```
// 当前屏幕 UV
float2 uv = input.uv;

// 读取已经渲染好的场景颜色
float3 color = SceneColorTexture.Sample(Sampler, uv).rgb;

// 对 color 做各种处理
color = PostProcess(color);

// 输出新的屏幕颜色
return float4(color, 1);
```

所以屏幕后处理的核心其实就是：

> **Fullscreen Pass（全屏 Pass） + 屏幕纹理采样 + 图像处理算法。**

---

# 二、屏幕后处理通常需要哪些 Buffer

很多后处理并不是只靠颜色图就能完成。

现代游戏通常会提供：

```
SceneColor
    场景颜色

SceneDepth
    场景深度

Normal
    法线

Velocity / Motion Vector
    运动矢量

Stencil
    模板

Exposure
    曝光数据

History Buffer
    上一帧数据
```

不同效果需要的数据不同。

|后处理|SceneColor|Depth|Normal|Velocity|History|
|---|---|---|---|---|---|
|Bloom|✓|||||
|Tone Mapping|✓|||||
|Color Grading|✓|||||
|Vignette|✓|||||
|FXAA|✓|||||
|DOF|✓|✓||||
|Motion Blur|✓|✓||✓||
|SSAO||✓|✓|||
|SSR|✓|✓|✓||常有|
|TAA|✓|✓||✓|✓|

可以记住：

> **简单颜色后处理看 SceneColor，高级屏幕空间效果一般还需要 Depth / Normal / Velocity / History。**

# 三、为什么很多后处理使用 Fullscreen Triangle

以前经常使用一个覆盖整个屏幕的 Quad：

```
(-1, 1) ---------- (1, 1)
   |                  |
   |                  |
   |                  |
(-1,-1) ---------- (1,-1)
```

由两个三角形组成。

现代引擎更常见的是：

> **Fullscreen Triangle**

一个超大的三角形覆盖整个屏幕。

示意：

```
          *
         / \
        /   \
       /屏幕 \
      /区域   \
     /         \
    *-----------*
```

原因之一是避免 Quad 中间存在三角形公共边：

```
┌───────────────┐
│\              │
│  \            │
│    \          │
│      \        │
│        \      │
└───────────────┘
```

GPU 通常以：

```
2×2 Pixel Quad
```

进行 Fragment Shader 执行。

Quad 中间那条边可能造成一些额外 helper pixel / quad 执行。

Fullscreen Triangle 可以减少这种问题。

# 四、Bloom —— 泛光

Bloom 是游戏中最常见的后处理之一。

效果：

```
普通光源：

   ●

Bloom：

   ✦
  ✦●✦
   ✦
```

也就是：

> 特别亮的区域向周围产生柔和的光晕。

---

## 1. Bloom 基本原理

Bloom 通常分 3 步：

```
HDR SceneColor
      ↓
提取高亮区域
Threshold
      ↓
高斯模糊 / Downsample Blur
      ↓
Bloom Texture
      ↓
和原画面相加
      ↓
最终结果
```

---

# 五、Bloom 第一步：亮度提取

假设：

```
float3 color;
```

计算亮度：

```
float luminance =
      color.r * 0.2126
    + color.g * 0.7152
    + color.b * 0.0722;
```

为什么绿色权重最高？

因为人眼对：

```
绿色
```

最敏感。

然后设置阈值：

```
if (luminance > threshold)
{
    bloomColor = color;
}
else
{
    bloomColor = 0;
}
```

例如：

```
threshold = 1.0
```

HDR 场景：

```
天空     0.7
墙壁     0.5
灯泡     8.0
太阳    50.0
```

只有：

```
灯泡
太阳
```

进入 Bloom。

---

# 六、Bloom 为什么必须搭配 HDR

如果使用普通 LDR：

```
颜色最大值 = 1
```

例如：

```
白墙
RGB = 1,1,1

太阳
RGB = 1,1,1
```

完全无法区分：

```
普通白色

和

极高亮度光源
```

HDR 中可以：

```
白墙：

1,1,1

灯：

10,8,5

太阳：

100,90,70
```

于是 Bloom 很容易判断：

```
超过 1 的区域
```

是真正高亮区域。

因此：

> Bloom 通常在 Tone Mapping 之前完成。

---

# 七、Bloom 第二步：模糊

最经典就是：

> Gaussian Blur（高斯模糊）

原理是：

```
当前像素颜色
=
周围像素颜色 × 权重
```

例如：

```
0.05  0.10  0.05
0.10  0.40  0.10
0.05  0.10  0.05
```

中间像素影响最大。

Shader 类似：

```
float3 color = 0;

color += Sample(uv + offset1) * weight1;
color += Sample(uv + offset2) * weight2;
color += Sample(uv)           * weightCenter;
```

最终亮区扩散：

```
原来：

      XX
      XX

模糊：

     ....
   ..XXXX..
  ..XXXXXX..
   ..XXXX..
     ....
```

---

# 八、高斯模糊为什么通常拆成两次

二维 Gaussian Blur：

```
NxN
```

例如：

```
9 × 9
```

一次需要：

```
81 次采样
```

非常贵。

但高斯核具有：

> 可分离性 Separable

所以：

```
二维模糊

可以拆成：

水平模糊
+
垂直模糊
```

变成：

```
9 + 9 = 18 次
```

而不是：

```
81 次
```

即：

```
原图
 ↓
Horizontal Blur
 ↓
Vertical Blur
 ↓
结果
```

这是经典面试题。

---

# 九、现代 Bloom：Downsample / Upsample

实际现代游戏不一定直接使用大半径 Gaussian Blur。

更常见的是：

```
1920×1080
   ↓
960×540
   ↓
480×270
   ↓
240×135
   ↓
120×67
```

逐级：

> Downsample（降采样）

然后再：

```
120
 ↓
240
 ↓
480
 ↓
960
 ↓
1080
```

逐级：

> Upsample（升采样）

并融合。

原因：

### 1. 更便宜

小纹理像素更少。

### 2. 自带大范围模糊

例如：

```
120 × 67
```

的一个像素放大回：

```
1920 × 1080
```

实际上覆盖很大的区域。

因此现代 Bloom 的核心经常是：

> **Mip Pyramid / Downsample Pyramid。**

# 十、Tone Mapping —— 色调映射

Tone Mapping 可以说是现代 HDR 渲染最重要的后处理之一。

因为 GPU 内部 HDR 颜色可能是：

```
0
1
5
20
100
10000
```

但显示器最终通常需要映射到：

```
0 ~ 1
```

因此需要：

> HDR → Display Range

---

# 十一、最简单 Tone Mapping：Reinhard

公式：

$C_{out}=\frac{C}{1+C}$

例如：

```
HDR       输出

0      -> 0
1      -> 0.5
2      -> 0.67
5      -> 0.83
10     -> 0.91
100    -> 0.99
```

可以看到：

```
输入再亮
输出也不会超过 1
```

代码：

```
float3 ToneMap(float3 color)
{
    return color / (color + 1.0);
}
```

优点：

```
简单
便宜
稳定
```

缺点：

```
画面对比度不足
容易发灰
```

---

# 十二、ACES Tone Mapping

现代引擎常用 ACES 或 ACES 风格曲线。

常见近似：

```
float3 ACES(float3 x)
{
    float a = 2.51;
    float b = 0.03;
    float c = 2.43;
    float d = 0.59;
    float e = 0.14;

    return saturate(
        (x * (a * x + b))
        /
        (x * (c * x + d) + e)
    );
}
```

大致曲线：

```
输出
1 ┤                  ______
  │              ___/
  │           __/
  │        __/
  │      _/
  │    _/
  │ __/
0 └────────────────────────
        输入亮度
```

三个重要区域：

```
Toe

Shadow
暗部柔和压缩

Linear / Midtones

主要颜色区域

Shoulder

Highlight
高光逐渐压缩
```

这样太阳、火焰、灯泡不会突然：

```
直接截断成纯白
```

而是：

```
平滑过渡到白色
```

# 十三、Exposure —— 自动曝光

很多游戏进入：

```
室内 → 室外
```

会出现：

```
刚出去非常亮
↓
几秒后恢复正常
```

或者：

```
室外 → 地洞

刚开始全黑
↓
逐渐能看到东西
```

这就是：

> Auto Exposure / Eye Adaptation  
> 自动曝光 / 眼睛适应

---

# 十四、曝光的基本公式

最简单可以理解为：

```
最终 HDR Color

=

SceneColor × Exposure
```

例如：

```
color *= exposure;
```

Exposure 高：

```
画面变亮
```

Exposure 低：

```
画面变暗
```

---

# 十五、怎么计算自动曝光

GPU 会统计整个屏幕的亮度。

现代方法常使用：

> Luminance Histogram（亮度直方图）

例如将亮度分成：

```
Bin0
Bin1
Bin2
...
Bin64
```

统计：

```
亮度范围       像素数量

0.001          500
0.01           8000
0.1           300000
1             700000
10            100000
100           200
```

然后估计：

```
Average Luminance
```

再计算目标曝光：

$$
 Exposure \propto \frac{MiddleGray}{AverageLuminance} 
$$

例如：

```
环境太亮

Average = 10

Exposure ↓
```

环境太暗：

```
Average = 0.1

Exposure ↑
```

---

# 十六、为什么曝光不能瞬间改变

如果每帧直接：

```
Exposure = TargetExposure
```

画面会不停：

```
亮
暗
亮
暗
亮
暗
```

因此需要平滑：

```
CurrentExposure =
    Lerp(
        CurrentExposure,
        TargetExposure,
        AdaptSpeed
    );
```

本质就是：

> 时间上的低通滤波 / 插值。

LUT：

> Lookup Table

本质就是：


例如原颜色：

# 十九、为什么 Color LUT 是 3D

颜色有三个维度：

```
R
G
B
```

所以理论 LUT 是：

```
3D Texture
```

坐标：

```
(R,G,B)
```

直接：

```
float3 result = LUT.Sample(
    sampler,
    color.rgb
```

```
     B
    /
   /
  ┌──── R
  │
  │
  G
```

每个 RGB 对应一个新 RGB。

```

```

来模拟 3D LUT。

# 二十、Vignette —— 暗角

Vignette 就是：

```
屏幕中心亮
屏幕边缘暗
```

视觉效果：

```
█████████████
██▓▓▓▓▓▓▓███
█▓▒▒▒▒▒▒▓██
█▓▒ 中心 ▒▓█
█▓▒▒▒▒▒▒▓██
██▓▓▓▓▓▓▓██
█████████████
```

实现非常简单。

---

# 二十一、Vignette 原理

计算当前像素到屏幕中心的距离：

```
float2 center = float2(0.5, 0.5);

float dist = distance(uv, center);
```

然后：

```
float vignette =
    smoothstep(
        inner,
        outer,
        dist
    );
```

最终：

```
color *= 1.0 - vignette;
```

于是：

```
中心：

dist = 0

几乎不变
```

边缘：

```
dist 大

颜色变暗
```

# 二十二、Chromatic Aberration —— 色差

中文一般叫：

> 色差 / 色散 / RGB 分离

效果：

```
正常：

██████

色差：

R
  G
    B
```

尤其屏幕边缘：

```
红绿蓝出现错位
```

---

# 二十三、色差怎么实现

正常采样：

```
float3 color =
    SceneColor.Sample(sampler, uv);
```

色差：

```
float r =
    SceneColor.Sample(
        sampler,
        uv + offset
    ).r;

float g =
    SceneColor.Sample(
        sampler,
        uv
    ).g;

float b =
    SceneColor.Sample(
        sampler,
        uv - offset
    ).b;
```

最后：

```
float3 color =
    float3(r,g,b);
```

通常 offset 与屏幕中心距离有关：

```
中心

色差很弱

屏幕边缘

色差更强
```

# 二十四、Film Grain —— 胶片噪点

Film Grain：

> 胶片颗粒

本质就是往颜色加入：

```
Noise
```

例如：

```
float noise = Random(uv);

color += noise * GrainIntensity;
```

但如果每帧完全随机：

```
噪点变化太剧烈
```

所以通常加入：

```
Time
FrameIndex
Blue Noise
```

例如：

```
noise =
    BlueNoiseTexture.Sample(
        sampler,
        uv + frameOffset
    );
```

Blue Noise 的视觉质量一般比简单 Random 更好。

# 二十五、Depth of Field —— 景深

DOF：

> Depth of Field  
> 景深

模拟真实相机：

```
焦点附近

清晰

前景

模糊

远景

模糊
```

例如：

```
相机

  ↓

模糊    清晰        模糊

人物A   人物B       背景
```

---

# 二十六、DOF 最核心的数据：Depth

需要：

```
Depth Buffer
```

获得每个像素距离相机多远。

然后和：

```
Focus Distance
```

比较。

例如：

```
Depth = 5m
Focus = 5m

↓

清晰
```

```
Depth = 20m
Focus = 5m

↓

模糊
```

---

# 二十七、Circle of Confusion

真正的 DOF 通常不是简单：

```
abs(depth - focus)
```

而是计算：

> Circle of Confusion，CoC  
> 弥散圆

简单理解：

```
CoC = 0

完全清晰
```

```
CoC 越大

越模糊
```

大致关系：

$$
 CoC \propto \left| \frac{z-f_{focus}}{z} \right| 
$$

实际物理相机还会考虑：

```
Focal Length
Aperture
Focus Distance
Sensor Size
```

---

# 二十八、DOF 后续做什么

计算完：

```
CoC
```

以后：

```
CoC 小

少量 Blur
```

```
CoC 大

大量 Blur
```

所以：

```
Depth
 ↓
CoC
 ↓
Blur Radius
 ↓
采样周围颜色
```

例如：

```
float coc =
    CalculateCoC(depth);

float3 blur =
    BlurScene(
        uv,
        coc
    );
```

---

# 二十九、Bokeh —— 散景

高级 DOF 会模拟：

> Bokeh

例如夜景灯光：

```
普通模糊：

  ****
 ******

Bokeh：

  ⬡
⬡ ⬡ ⬡
```

形状可能和相机光圈有关：

```
六边形
八边形
圆形
```

因为现实相机的光圈叶片会影响散景形状。

# 三十、Motion Blur —— 运动模糊

运动模糊效果：

```
物体高速移动

正常：

[车]

运动模糊：

====[车]====
```

或者快速旋转相机：

```
整个画面产生拖影
```

---

# 三十一、Motion Blur 的关键：Velocity Buffer

现代运动模糊通常不会：

```
随便把画面 Blur
```

而是需要：

> Motion Vector / Velocity Buffer  
> 运动矢量缓冲

记录：

```
当前像素

上一帧在哪里
```

或者反过来：

```
上一帧位置
→
当前帧位置
```

例如：

```
上一帧

x = 200

当前帧

x = 230

Motion Vector：

(+30, 0)
```

---

# 三十二、运动矢量怎么计算

一般通过：

```
当前帧 Clip Position

和

上一帧 Clip Position
```

计算。

Vertex Shader：

```
currentPos =
    CurrentViewProjection
    *
    CurrentModel
    *
    vertex;

previousPos =
    PreviousViewProjection
    *
    PreviousModel
    *
    vertex;
```

转换为 NDC 后：

```
velocity =
    currentNDC
    -
    previousNDC;
```

写入：

```
Velocity Buffer
```

---

# 三十三、Motion Blur 怎么使用 Velocity

例如：

```
Velocity:

→→→→
```

Shader 沿 Velocity 方向采样：

```
color =
      Sample(uv)
    + Sample(uv + velocity * 0.2)
    + Sample(uv + velocity * 0.4)
    + Sample(uv + velocity * 0.6)
    + Sample(uv + velocity * 0.8);
```

然后平均。

于是：

```
运动方向上的颜色被拉开
```

产生运动模糊。

---

# 三十四、FXAA —— 快速近似抗锯齿

FXAA：

> Fast Approximate Anti-Aliasing  
> 快速近似抗锯齿

它完全是一种：

> Screen Space 后处理 AA

不需要修改几何阶段。

---

# 三十五、FXAA 的核心思想

首先寻找：

```
高对比度边缘
```

例如：

```
白白白黑黑黑
白白白黑黑黑
白白白黑黑黑
```

计算：

```
当前像素亮度

周围像素亮度
```

如果差异很大：

```
这里可能是边缘
```

然后判断：

```
水平边

还是

垂直边
```

最后：

```
沿边缘方向重新采样
```

把锯齿：

```
████
   ████
      ████
```

变成视觉上更平滑的：

```
▓███
 ▓███
   ▓███
```

---

# 三十六、FXAA 优缺点

优点：

```
非常快

只需要 SceneColor

实现简单

适合低端设备
```

缺点：

```
本质是识别边缘后 Blur

容易让画面变糊
```

特别是：

```
文字
UI
细线
细小纹理
```

可能一起被模糊。

---

# 三十七、SMAA

SMAA：

> Subpixel Morphological Anti-Aliasing

相比 FXAA：

```
更精确地识别边缘形态
```

通常包含几个阶段：

```
Edge Detection
      ↓
Search Pattern
      ↓
Blend Weight
      ↓
Neighborhood Blending
```

质量通常：

```
SMAA > FXAA
```

但：

```
性能开销也更大
```

---

# 三十八、TAA —— 时间抗锯齿

TAA：

> Temporal Anti-Aliasing  
> 时间抗锯齿

这是现代游戏最重要的技术之一。

UE 中长期大量使用：

```
TAA
TSR
```

它与 FXAA 最大区别：

```
FXAA

只看当前帧
```

```
TAA

当前帧
+
上一帧
+
历史帧
```

---

# 三十九、TAA 最基本思想

假设一个像素内部有一个细小三角形：

```
┌───────┐
│   /   │
│  /    │
│ /     │
└───────┘
```

正常每帧：

```
一个 Pixel 只能采一次
```

可能无法正确覆盖。

TAA 会让摄像机每帧：

> Jitter（抖动）

例如：

```
Frame 1:

(+0.25,+0.25)

Frame 2:

(-0.25,+0.25)

Frame 3:

(+0.25,-0.25)

Frame 4:

(-0.25,-0.25)
```

这样不同帧采到：

```
像素内部不同位置
```

最后：

```
历史帧累积
```

相当于增加采样数量。

---

# 四十、TAA 基本公式

最简单：

 C_{final} = \alpha C_{current} + (1-\alpha)C_{history} 

例如：

```
float3 finalColor =
    lerp(
        HistoryColor,
        CurrentColor,
        0.1
    );
```

相当于：

```
历史信息 90%

当前信息 10%
```

但实际不能这么简单。

否则会产生：

> Ghosting（鬼影）。

---

# 四十一、为什么 TAA 需要 Motion Vector

假设：

```
人物这一帧在 x=500

上一帧在 x=450
```

那么：

```
当前 Pixel
```

不能直接：

```
History.Sample(currentUV)
```

因为上一帧同一个物体不在这里。

必须：

```
currentUV
    ↓
Motion Vector
    ↓
找到 PreviousUV
```

即：

```
float2 previousUV =
    currentUV
    -
    velocity;
```

然后：

```
history =
    HistoryTexture.Sample(
        sampler,
        previousUV
    );
```

这个过程叫：

> Reprojection  
> 重投影

---

# 四十二、TAA Ghosting 为什么产生

假设上一帧：

```
背景

AAAAA

人物

XXXXX
```

人物快速离开以后：

```
这里应该恢复背景
```

但历史 Buffer 仍然：

```
XXXXX
```

如果继续累积：

```
History + Current
```

就产生：

```
半透明残影
```

所以高级 TAA 会使用：

```
Neighborhood Clamping
Variance Clipping
Depth Rejection
Velocity Rejection
Disocclusion Detection
```

来判断：

```
历史数据还能不能使用。
```

---

# 四十三、SSAO —— 屏幕空间环境光遮蔽

SSAO：

> Screen Space Ambient Occlusion  
> 屏幕空间环境光遮蔽

效果主要发生在：

```
墙角
缝隙
物体接触区域
凹槽
```

例如：

```
没有 AO：

墙
│
│____地面

墙角亮度差不多
```

加入 AO：

```
墙
│▓
│▓▓___地面
```

角落变暗。

---

# 四十四、SSAO 的核心思想

假设当前像素：

```
P
```

通过 Depth 重建：

```
View Space Position
```

然后在 P 周围生成随机采样：

```
    •
 •  •  •
   \|/
•---P---•
   /|\
 •  •  •
```

如果周围很多采样点：

```
被其他几何体挡住
```

说明这里是：

```
凹陷区域
```

于是：

```
AO 更强
```

最终：

```
AmbientLight *= AO
```

---

# 四十五、SSAO 为什么需要 Depth + Normal

Depth 用来：

```
恢复当前像素空间位置
```

Normal：

```
确定半球采样方向
```

因为不应该：

```
向模型内部采样
```

而是：

```
围绕表面法线
```

构造半球：

```
        ↑ Normal
      • • •
    •   •   •
  •     P     •
────────────── 表面
```

---

# 四十六、SSAO 的问题

因为它只有屏幕信息：

```
看不到屏幕外
看不到被挡住的物体
```

所以：

> SSAO 是近似算法。

还容易出现：

```
Halo
Noise
Banding
Flicker
```

因此通常需要：

```
Blur
Temporal Filter
Depth-aware Blur
```

---

# 四十七、Bilateral Blur —— 双边滤波

这是 SSAO 等算法里非常重要的一个概念。

普通 Blur：

```
只看位置距离
```

会导致：

```
AO 从人物身上模糊到背景
```

造成黑边。

Bilateral Blur 额外考虑：

```
Depth Difference
Normal Difference
```

即：

```
距离近
+
深度相近
+
法线相近
```

才互相 Blur。

权重大致：

 W = W_{distance} \times W_{depth} \times W_{normal} 

于是可以做到：

> 保边模糊 Edge-Preserving Blur。

这是非常常见的后处理优化技术。

---

# 四十八、SSR —— 屏幕空间反射

SSR：

> Screen Space Reflection  
> 屏幕空间反射

例如湿地：

```
人物
  ↓

──────── 地面

  ↑
人物倒影
```

---

# 四十九、SSR 的核心原理

SSR 使用：

```
Depth
Normal
SceneColor
```

首先获得当前 Pixel：

```
P
```

表面法线：

```
N
```

观察方向：

```
V
```

计算反射方向：

 R = reflect(-V,N) 

然后沿：

```
R
```

在屏幕空间不断向前走：

```
P
 \
  \
   •
    •
     •
      •
```

这叫：

> Ray Marching（光线步进）。

---

# 五十、SSR 怎么判断撞到物体

每走一步：

```
计算当前 Ray 的深度
```

同时读取：

```
Depth Buffer
```

如果：

```
RayDepth

接近

SceneDepth
```

说明：

```
Ray 和场景几何表面相交
```

然后：

```
读取那个屏幕位置的 SceneColor
```

作为反射颜色。

---

# 五十一、SSR 最大问题

它叫：

> Screen Space Reflection

所以只能反射：

```
当前屏幕能看到的东西
```

如果物体：

```
在屏幕外
```

SSR：

```
完全不知道它存在
```

例如：

```
镜子本应该反射后面的角色

但角色不在当前屏幕

↓

SSR 没法反射
```

因此经常配合：

```
Reflection Capture
Probe
Ray Tracing
Lumen
Cubemap
```

作为 fallback。

---

# 五十二、Screen Space Fog

一种简单雾效也可以完全作为后处理实现。

基本公式：

$$
 Color= SceneColor(1-Fog) + FogColor \times Fog 
$$

Fog 可以根据 Depth：

```
float fog =
    saturate(
        depth / FogDistance
    );
```

然后：

```
color =
    lerp(
        SceneColor,
        FogColor,
        fog
    );
```

于是：

```
近处

SceneColor 更多

远处

FogColor 更多
```

---

# 五十三、指数雾

更自然的写法：

 Fog = 1-e^{-density \times distance} 

例如：

```
float fog =
    1.0 -
    exp(
        -density * distance
    );
```

这样远处逐渐进入浓雾，而不是线性变化。

# 五十四、Outline —— 描边

游戏中：

```
敌人高亮
交互物描边
被遮挡角色描边
```

也经常使用后处理。

一种经典方法：

```
Depth Edge Detection
```

例如采样：

```
中心 depth

左 depth
右 depth
上 depth
下 depth
```

如果：

```
Depth 差异很大
```

说明这里可能是：

```
物体轮廓
```

---

# 五十五、Normal 描边

还可以比较：

```
Normal
```

比如两个表面：

```
法线方向变化很大
```

即使 Depth 类似，也可以检测出：

```
模型折角
```

所以高级 Outline：

```
Depth Edge

+

Normal Edge
```

一起判断。

# 五十六、Stencil 描边

游戏开发非常常见。

例如：

```
Boss
```

先写：

```
Stencil = 1
```

后处理 Shader：

```

{
    DrawOutline();
}
```

这样可以只描：

```
指定对象
```

UE 的：


就是做这种效果的经典方式。

# 五十七、Sharpen —— 锐化

TAA / Upscaling 后画面经常变糊，因此会做：

> Sharpening

最简单思路：

```
高频信息
=
原图
-
模糊图
```

然后：

```
最终

=

原图

+

高频 × 强度
```

即：

$$
 C_{sharp} = C + k(C-C_{blur}) 
$$

这就是经典：

> Unsharp Mask。

---

# 五十八、Upscaling 也属于现代后处理的重要组成部分

现代游戏常见：

```
实际渲染：

1920 × 1080

最终输出：

3840 × 2160
```

然后使用：

```
TAAU
TSR
DLSS
FSR
XeSS
```

恢复细节。

其中：

```
TAAU / TSR
```

本质上大量依赖：

```

History
Motion Vector
Depth
Jitter
```

和 TAA 原理非常接近。

可以理解成：

> Temporal AA + Reconstruction + Upsampling。

# 五十九、后处理最重要的一个概念：Temporal Filter

现代游戏很多效果：

```
SSAO
SSR
RTGI
Ray Traced Reflection
TAA
TSR
DOF
Volumetric Fog
```

都会用：

> Temporal Accumulation  
> 时间累积

原因是：

```
一帧算很多样本

↓

性能太高
```

于是变成：

```
每帧只算少量 Sample

+

历史帧复用
```

例如：

```
Frame1：

Sample A

Frame2：

Sample B

Frame3：

Sample C

Frame4：

Sample D
```

累积后近似：

```
A+B+C+D
```

所以现代实时渲染一个非常重要的设计思想就是：

> **空间采样不足，就利用时间维度补充采样。**

# 六十、为什么 Temporal 技术这么容易产生鬼影

因为它假设：

```
过去的数据

仍然能够代表现在
```

但是场景一旦：

```

相机移动
物体消失
遮挡关系改变
光照改变
```

历史数据就可能失效。

因此所有 Temporal Algorithm 都要解决：

```
Reprojection

History Validation

Disocclusion

Clamping

Ghosting

Flicker
```

# 六十九、面试最容易问的几个问题

### Q1：为什么 Bloom 一般在 Tone Mapping 前？

因为 Bloom 需要利用 HDR 的高亮信息：

```
SceneColor = 10
20
100
```

Tone Mapping 后这些高亮已经被压缩到：

```
0~1
```

会丢失“到底有多亮”的信息。

---

### Q2：为什么 Gaussian Blur 要做 Horizontal + Vertical？

因为二维 Gaussian Filter：

```
N × N
```

可以拆成：

```
N × 1

+

1 × N
```

把：

```
N² 次采样
```

降低为：

```
2N 次采样。
```

---

### Q3：为什么 SSAO 会有噪点？

因为每个 Pixel 不可能采样非常多的 Sample：

```
4
8
16
```

属于低采样近似，因此产生：

```
Noise
```

通常通过：

```
Spatial Blur
+
Temporal Filter
```

处理。

---

### Q4：SSR 最大缺点是什么？

只拥有：

```
当前屏幕的数据
```

所以：

```
屏幕外
被遮挡
背后的物体
```

无法正确反射。

---

### Q5：为什么 TAA 会产生鬼影？

因为它：

```
复用了历史帧
```

如果：

```
History Reprojection 错误

或者

历史数据已经失效
```

旧颜色会被带入当前帧，形成残影。

---

### Q6：为什么 Motion Blur 和 TAA 都需要 Velocity Buffer？

因为都需要知道：

```
一个 Pixel / Object

从上一帧到当前帧

发生了多少屏幕空间位移。
```

Motion Blur 用它决定：

```
模糊方向
```

TAA 用它：

```
重投影历史帧。
```

---

# 七十、一句话理解每种常见后处理

可以最后这样背：

```

=

=

=

=

=

=

=

=
```

如果把整个现代游戏屏幕后处理压缩成一条主线，其实就是：

```
                    Scene Rendering
                           │
                           ▼
                    HDR SceneColor
                           │
             ┌─────────────┼──────────────┐
             ▼             ▼              ▼
           Depth         Normal        Velocity

                    ▼             ▼
              SSAO / SSR      MotionBlur

                    ▼
              DOF / Bloom

              Auto Exposure
                    │
                    ▼

                    │

                    │
                    ▼
       Vignette / Grain / Chromatic
                    │
                    ▼
                 最终画面
```

对游戏客户端面试来说，**最需要真正理解而不是死记的四条主线**是：`Bloom 的多级降采样`、`SSAO/SSR 的屏幕空间思想`、`TAA 的 Jitter + 重投影 + History`、以及 `HDR → Exposure → Tone Mapping → Color Grading` 这一整套颜色管线。把这四块搞透，大多数常见后处理问题就能串起来。
