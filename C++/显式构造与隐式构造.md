# C++ 显式构造与隐式构造详解

在 C++ 中，**显式构造（Explicit Construction）和隐式构造（Implicit Construction）**是非常重要的知识点，尤其是在 C++ 类型转换、构造函数、对象初始化以及 UE 游戏客户端开发中。

其中最核心的关键字就是 `explicit`。

需要先明确一点：

- 显式构造：程序员明确指定使用某个构造函数创建对象。
    
- 隐式构造：编译器根据上下文，自动通过构造函数完成类型转换并创建对象。
    
- `explicit` 关键字：限制构造函数参与隐式类型转换，不是禁止该构造函数被调用。

严格来说，C++ 标准更常使用 隐式转换（Implicit Conversion）、转换构造函数（Converting Constructor） 和 初始化（Initialization） 等术语。

下面从底层原理、代码示例、初始化方式、`explicit` 的作用及常见面试题进行讲解。

## 一、什么是隐式构造？

先看一个非常典型的例子。

```
#include <iostream>

class Player
{
public:
    int Level;

    // 普通构造函数，没有 explicit
    Player(int InLevel)
        : Level(InLevel)
    {
        std::cout << "Player(int) 被调用\n";
    }
};

int main()
{
    // 方式1：直接初始化
    Player P1(10);

    // 方式2：拷贝初始化
    Player P2 = 10;

    // 方式3：列表初始化
    Player P3{10};

    return 0;
}
```

上面三种方式都可以创建 `Player` 对象。

其中：

```
Player P2 = 10;
```

是需要重点理解的。

`10` 是 `int` 类型，而 `P2` 是 `Player` 类型。

为什么能够把 `int` 赋给 `Player`？

因为 `Player` 提供了一个允许隐式转换的构造函数：

```
Player(int InLevel);
```

编译器可以利用这个构造函数完成：

```
int → Player
```

的转换。

### 1. 隐式构造的执行过程

```
Player P2 = 10;
```

可以从概念上理解为：

<img width="741" height="316" alt="image" src="https://github.com/user-attachments/assets/80368188-afa4-4db2-9e1a-f403fac33cb5" />

这里需要特别注意：

`Player P2 = 10` 并不是先构造临时对象，再调用拷贝构造函数。

这里的 `=` 是拷贝初始化语法，而不是赋值运算。

对于这个例子，编译器可以通过 `Player(int)` 直接初始化 `P2`，不需要额外调用拷贝构造函数。

## 二、什么是显式构造？

在构造函数前面添加 `explicit` 关键字。

```
class Player
{
public:
    int Level;

    // 显式构造函数
    explicit Player(int InLevel)
        : Level(InLevel)
    {
    }
};
```

再来看不同的初始化方式：

```
int main()
{
    // 正确：直接初始化
    Player P1(10);

    // 正确：直接列表初始化
    Player P2{10};

    // 错误：不允许通过 int 隐式转换为 Player
    // Player P3 = 10;

    // 错误：拷贝列表初始化不能选择 explicit 构造函数
    // Player P4 = {10};

    // 正确：明确构造一个 Player 对象
    Player P5 = Player(10);

    return 0;
}
```

对比结果：

|初始化方式|无 `explicit`|有 `explicit`|
|---|---|---|
|`Player p(10)`|||
|`Player p{10}`|||
|`Player p = 10`|||
|`Player p = {10}`|||
|`Player p = Player(10)`|||

结论：`explicit` 限制的是隐式转换，而不是构造函数本身。

即使构造函数被声明为 `explicit`，依然可以通过直接初始化调用。

## 三、C++ 的四种常见初始化方式

这是理解显式构造和隐式构造最重要的基础，也是高频面试问题。

### 1. 直接初始化（Direct Initialization）

```
Player P1(10);
```

特点：

- 明确指定构造参数。
    
- 可以调用 `explicit` 构造函数。
    
- 可以参与构造函数重载决议。

### 2. 拷贝初始化（Copy Initialization）

```
Player P2 = 10;
```

特点：

- `=` 在这里不代表调用赋值运算符。
    
- 允许使用符合条件的隐式转换。
    
- 不会选择 `explicit` 构造函数来完成这种转换。

注意区分以下代码：

```
Player P1 = 10; // 初始化：调用转换构造函数

Player P2(20);

P2 = P1;        // 赋值：调用拷贝赋值运算符
```

第一种属于对象初始化，第三种才属于对象赋值。

### 3. 直接列表初始化（Direct List Initialization）

```
Player P3{10};
```

特点：

- 可以调用 `explicit` 构造函数。
    
- 会防止某些窄化转换（Narrowing Conversion）。
    
- 会优先考虑合适的 `std::initializer_list` 构造函数。

例如：

```
class Test
{
public:
    explicit Test(double Value) {}
};

Test T1(3.14);  // 正确
Test T2{3.14};  // 正确

// Test T3{3.14f}; 
// 是否允许取决于具体目标类型和窄化转换规则
```

更典型的窄化例子：

```
int A(3.14); // 允许，结果通常为 3

// int B{3.14}; // 编译错误：double 到 int 的窄化转换
```

### 4. 拷贝列表初始化（Copy List Initialization）

```
Player P4 = {10};
```

这与 `Player P4{10}` 有重要区别。

```
class Player
{
public:
    explicit Player(int Level) {}
};

Player P1{10};      // 正确

// Player P2 = {10}; // 错误
```

在拷贝列表初始化中，如果重载决议最终选中的是 `explicit` 构造函数，那么程序就是不合法的。

这里的区别属于面试中非常容易混淆的知识点。

## 四、为什么 C++ 需要 explicit？

核心原因是：

防止隐式类型转换导致代码语义不清、错误调用以及潜在 Bug。

来看一个实际例子。

```
#include <iostream>

class Health
{
public:
    int Value;

    Health(int InValue)
        : Value(InValue)
    {
    }
};

void ApplyHealth(Health InHealth)
{
    std::cout << InHealth.Value << "\n";
}

int main()
{
    ApplyHealth(100);

    return 0;
}
```

虽然函数参数是：

```
void ApplyHealth(Health InHealth)
```

但是：

```
ApplyHealth(100);
```

可以正常编译。

原因是：

```
100
  ↓
Health(100)
  ↓
ApplyHealth(Health对象)
```

也就是说，编译器自动把整数构造成了 `Health` 对象。

这种行为不一定错误，但有时会引入隐患。

假设项目中存在多个整数类型：

```
void ApplyHealth(Health InHealth);
```

调用方可能写错：

```
int PlayerId = 1001;

// 本来想传递一个玩家ID
// 结果被隐式构造为 Health
ApplyHealth(PlayerId);
```

代码依然编译成功，但逻辑语义已经错误。

### 使用 explicit 改进

```
class Health
{
public:
    int Value;

    explicit Health(int InValue)
        : Value(InValue)
    {
    }
};

void ApplyHealth(Health InHealth)
{
}

int main()
{
    int PlayerId = 1001;

    // 错误：不能隐式转换
    // ApplyHealth(PlayerId);

    // 正确：明确创建 Health
    ApplyHealth(Health(100));

    // 正确：显式使用列表初始化
    ApplyHealth(Health{100});
}
```

这样做的好处是调用者必须清楚地表达：

我传递的不是一个普通整数，而是一个 Health 对象。

这对于大型游戏项目中的属性值、技能 ID、角色 ID、网络消息类型等尤其有意义。

## 五、带默认参数的构造函数也可能发生隐式转换

这也是 C++ 面试中的一个常见陷阱。

很多人认为只有一个参数的构造函数才需要使用 `explicit`。

实际上并不准确。

```
class Player
{
public:
    Player(int InLevel, int InHp = 100)
    {
    }
};
```

这个构造函数虽然声明了两个参数，但第二个参数存在默认值。

所以：

```
Player P = 10;
```

仍然可以编译。

相当于通过：

```
Player(10, 100);
```

初始化对象。

因此：

判断构造函数是否允许单个值的隐式转换，关键不只是参数总数，而是它能否用一个实参调用，以及是否受到 `explicit` 限制。

可以写成：

```
class Player
{
public:
    explicit Player(int InLevel, int InHp = 100)
    {
    }
};
```

此时：

```
Player P1(10);   // 正确
Player P2{10};   // 正确

// Player P3 = 10; // 错误
```

## 六、explicit 也可以修饰多参数构造函数

从 C++11 开始，列表初始化使多参数构造函数也可能参与隐式转换。

```
struct Vector2
{
    float X;
    float Y;

    Vector2(float InX, float InY)
        : X(InX), Y(InY)
    {
    }
};

int main()
{
    Vector2 V1(1.0f, 2.0f);

    Vector2 V2{1.0f, 2.0f};

    Vector2 V3 = {1.0f, 2.0f};
}
```

如果添加 `explicit`：

```
struct Vector2
{
    float X;
    float Y;

    explicit Vector2(float InX, float InY)
        : X(InX), Y(InY)
    {
    }
};
```

此时：

```
Vector2 V1(1.0f, 2.0f);   // 正确

Vector2 V2{1.0f, 2.0f};   // 正确

// Vector2 V3 = {1.0f, 2.0f}; // 错误
```

所以并不能简单说：

> explicit 只能修饰单参数构造函数。

更准确的说法是：

`explicit` 可以修饰构造函数，用来限制其参与隐式转换和某些初始化形式。

## 七、explicit 与函数参数传递

下面把三种常用的函数参数形式放在一起比较。

```
class Value
{
public:
    explicit Value(int InValue)
    {
    }
};

// 按值传递
void Func1(Value V)
{
}

// 常量引用
void Func2(const Value& V)
{
}

// 右值引用
void Func3(Value&& V)
{
}
```

调用：

```
int main()
{
    // 错误：不允许隐式转换
    // Func1(10);
    // Func2(10);
    // Func3(10);

    // 正确：显式构造对象
    Func1(Value(10));
    Func2(Value(10));
    Func3(Value(10));

    return 0;
}
```

需要注意，这三种函数参数传递方式涉及不同的对象生命周期及引用绑定规则，但是这里有一个共同点：

如果希望用 `int` 作为调用参数，就需要进行 `int → Value` 转换。

当转换需要调用 `explicit` 构造函数时，就不能直接传递 `10`。

## 八、explicit 与返回值

返回语句也需要重点理解。

```
class Value
{
public:
    explicit Value(int InValue)
    {
    }
};

Value CreateValue()
{
    // 错误：返回值不能通过这种形式隐式构造
    // return 100;

    // 正确
    return Value(100);
}
```

也可以这样：

```
Value CreateValue()
{
    return Value{100};
}
```

这里还有一个相关的高频面试考点：

C++17 的保证拷贝消除（Guaranteed Copy Elision）。

例如：

```
Value CreateValue()
{
    return Value{100};
}
```

在 C++17 及之后的标准中，这种返回同类型纯右值的情况可以直接初始化函数的返回结果对象，而不需要额外调用移动构造或拷贝构造函数。

因此，`explicit` 不等于强制发生一次额外拷贝。

## 九、explicit 与拷贝构造函数

`explicit` 不仅可以修饰普通构造函数，还可以修饰拷贝构造函数。

例如：

```
class Test
{
public:
    Test() = default;

    explicit Test(const Test& Other)
    {
    }
};
```

此时：

```
int main()
{
    Test A;

    // 正确：直接初始化
    Test B(A);

    // 正确：直接列表初始化
    Test C{A};

    // 错误：拷贝初始化不能选中 explicit 拷贝构造函数
    // Test D = A;
}
```

这个知识点比较容易被忽略。

普通类的拷贝构造函数通常不会加 `explicit`，因为那样会限制许多常见的按值传参和对象拷贝初始化写法。

例如：

```
void Process(Test InTest);

Test A;

// Process(A); // 如果只有 explicit 拷贝构造函数可用，将无法这样按值传参
```

因此在工程实践中，通常重点考虑给转换构造函数使用 `explicit`，而不是默认把拷贝构造函数也声明为 `explicit`。

## 十、explicit 与类型转换运算符

这是一个扩展知识点，在面试中也比较常见。

`explicit` 除了修饰构造函数，还可以修饰自定义类型转换运算符。

例如：

```
class Player
{
public:
    int Hp = 100;

    explicit operator bool() const
    {
        return Hp > 0;
    }
};
```

调用：

```
int main()
{
    Player P;

    // 正确：if 条件允许对 explicit operator bool
    // 进行上下文转换
    if (P)
    {
        // 玩家存活
    }

    // 错误：普通拷贝初始化不允许使用
    // explicit operator bool
    // bool IsAlive = P;

    // 正确：显式类型转换
    bool IsAlive = static_cast<bool>(P);
}
```

这里有一个很重要的细节：

`explicit operator bool()` 不代表对象不能直接放进 `if` 条件。

因为 C++ 对条件语境中的 `bool` 转换有专门规则。

这也是现代 C++ 经常使用 `explicit operator bool()` 的原因之一。

例如智能指针经常可以这样写：

```
std::unique_ptr<int> Ptr = std::make_unique<int>(10);

if (Ptr)
{
    // 智能指针非空
}
```

它能够用于条件判断，但不会随意隐式转换为普通整数。

## 十一、C++20 的 explicit(bool)

从 C++20 开始，可以使用条件式 `explicit`。

语法：

```
explicit(条件表达式)
```

例如：

```
class Test
{
public:
    explicit(true) Test(int Value)
    {
    }

    explicit(false) Test(double Value)
    {
    }
};
```

其中：

|写法|含义|
|---|---|
|`explicit(true)`|等价于 `explicit`|
|`explicit(false)`|等价于不写 `explicit`|

因此：

```
Test A(10);       // 正确

// Test B = 10;   // 这里存在更优的 explicit Test(int) 候选，编译错误

Test C = 3.14;    // 正确，可以调用 Test(double)
```

注意 `Test B = 10` 这个例子。

虽然还有一个非 `explicit` 的 `Test(double)` 构造函数，但这并不意味着编译器一定会退而求其次选择它。重载决议和 `explicit` 的限制需要按对应初始化规则综合判断。

### 条件式 explicit 的典型使用场景

它主要用于泛型编程。

```
#include <type_traits>
#include <utility>

template<typename T>
class Box
{
public:
    T Data;

    template<typename U>
    explicit(!std::is_convertible_v<U, T>)
    Box(U&& Value)
        : Data(std::forward<U>(Value))
    {
    }
};
```

这里的含义是：

如果 `U` 能隐式转换为 `T`，那么这个构造函数就允许隐式构造。

反之，构造函数会被标记为显式构造。

这个功能适合实现泛型容器、包装类型等代码，属于进阶知识。

## 十二、常见面试陷阱：explicit 与 std::vector

这是非常经典的 C++ 初始化问题。

```
#include <vector>

int main()
{
    std::vector<int> A(3);

    std::vector<int> B{3};

    // std::vector<int> C = 3; // 错误
}
```

它们到底有什么区别？

<img width="741" height="150" alt="image" src="https://github.com/user-attachments/assets/58e7e035-0f55-4b84-92fb-b70de101e2c5" />

原因：

```
std::vector<int> A(3);
```

调用的是用于指定元素数量的构造函数。

其相关声明可简化理解为：

```
explicit vector(size_type count);
```

而：

```
std::vector<int> B{3};
```

优先匹配：

```
vector(std::initializer_list<int> init);
```

因此 `B` 中只有一个元素 `3`。

`explicit` 只是这个例子的一部分，另一个关键知识点是列表初始化时对 `initializer_list` 构造函数的优先选择。

## 十三、隐式构造和编译器隐式生成构造函数的区别

这里还存在一个容易混淆的问题。

C++ 中的“隐式构造函数”可能指两件不同的事情：

第一种：允许隐式转换的转换构造函数。

```
class A
{
public:
    A(int Value) {}
};

A Obj = 10;
```

这里讨论的是 `int` 到 `A` 的隐式转换。

第二种：编译器隐式声明或定义的特殊成员函数。

例如：

```
class Player
{
public:
    int Hp = 100;
};
```

由于没有用户声明的构造函数，编译器可以隐式声明默认构造函数。

```
Player P;
```

类似地，对于符合条件的类，编译器也会隐式声明拷贝构造、移动构造等特殊成员函数。

这两个概念虽然都有“隐式”二字，但含义完全不同：

|类型|关注点|
|---|---|
|隐式转换构造|是否允许从其他类型自动转换并构造对象|
|隐式声明的构造函数|编译器是否自动提供默认、拷贝、移动等构造函数|

面试时一定要先区分这两个概念。

## 十四、UE 游戏客户端开发中的实际应用

在 UE 项目中，`explicit` 比较适合用于封装具有明确语义的参数。

例如定义技能 ID：

```
struct FSkillId
{
    int32 Value;

    explicit FSkillId(int32 InValue)
        : Value(InValue)
    {
    }
};
```

然后定义技能释放接口：

```
void CastSkill(FSkillId SkillId)
{
    // 根据技能ID释放技能
}
```

调用：

```
int32 PlayerId = 1001;

// 错误：普通整数不能自动构造 FSkillId
// CastSkill(PlayerId);

// 正确：明确传入技能ID
CastSkill(FSkillId(1001));

// 正确：使用列表初始化
CastSkill(FSkillId{1001});
```

这对大规模 C++ 游戏项目的价值主要在于：

- 减少语义不同但底层类型相同的参数被误传。
    
- 让函数调用的意图更加明确。
    
- 防止部分隐式类型转换带来的隐藏错误。
    
- 在编译阶段发现部分参数类型问题，而不是运行阶段才暴露。

不过，并不是所有构造函数都必须添加 `explicit`。有些类型设计上就希望支持自然的隐式转换，此时不使用 `explicit` 也是合理的。

## 十五、C++ 高频面试题总结

|面试问题|核心答案|
|---|---|
|1. 什么是隐式构造？|编译器利用符合条件的构造函数自动完成类型转换和对象初始化|
|2. `explicit` 有什么作用？|限制构造函数参与隐式转换|
|3. `explicit` 会禁止构造函数调用吗？|不会，直接初始化仍然可以调用|
|4. `A a = 10` 是赋值吗？|不是，是拷贝初始化|
|5. `A a = 10` 一定调用拷贝构造吗？|不一定，通常可直接通过转换构造函数初始化对象|
|6. `A a(10)` 和 `A a = 10` 有何区别？|前者是直接初始化，后者是拷贝初始化，参与的构造函数规则不同|
|7. `A a{10}` 可以调用 explicit 吗？|可以|
|8. `A a = {10}` 可以调用 explicit 吗？|如果重载决议选中 explicit 构造函数，则程序不合法|
|9. explicit 只能用于单参数构造函数吗？|不是，多参数、拷贝构造函数等也可以使用|
|10. 带默认参数的构造函数可能发生隐式转换吗？|可以，只要存在符合条件的转换路径|
|11. explicit 可以用于类型转换运算符吗？|可以，例如 `explicit operator bool()`|
|12. C++20 新增了什么？|条件式 `explicit(bool)`|

## 最后总结

用一段代码记住整个知识点：

```
class A
{
public:
    explicit A(int Value) {}
};

int main()
{
    A a1(10);       // 正确：直接初始化

    A a2{10};       // 正确：直接列表初始化

    // A a3 = 10;   // 错误：隐式转换被禁止

    // A a4 = {10}; // 错误：拷贝列表初始化选中 explicit

    A a5 = A(10);   // 正确：明确创建 A 对象
}
```

面试中最重要的三句话：

1. `explicit` 主要用于防止不希望发生的隐式类型转换。
    
2. 直接初始化允许调用 `explicit` 构造函数，拷贝初始化不允许用它完成隐式转换。
    
3. `A a = 10` 是拷贝初始化，不代表一定发生拷贝构造；`=` 也不是在这里调用赋值运算符。

对于 UE 游戏客户端 C++ 面试，建议将这个知识点与构造函数重载决议、拷贝构造、移动构造、左值右值、完美转发以及 `std::initializer_list` 一起掌握，因为实际面试经常会将这些机制结合起来考察。
