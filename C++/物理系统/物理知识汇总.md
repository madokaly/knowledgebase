如果面试的是**动作游戏 / 战斗开发**，物理系统一般不会像“物理引擎开发岗”那样考你推导完整刚体求解器，而是更偏向：

**你能不能理解碰撞检测、角色运动、攻击判定、穿透问题，并且把物理系统正确地用在战斗系统里。**

尤其是《鸣潮》这种高速动作游戏，物理相关问题往往会和**攻击判定、角色移动、闪避、格挡、受击、投射物、网络同步**结合起来问。

我建议你重点准备下面这些内容。

# 2. Sweep：战斗开发非常重要

正确思路通常不是只检查“当前位置”。

而是检测：

```
上一帧位置
↓
当前帧位置
```

之间扫过的空间。

例如刀刃上放几个采样点：

```
Sword Root
    |
    |---- P1
    |
    |---- P2
    |
    |---- P3
```

记录：

```
LastFramePosition
CurrentFramePosition
```

然后：

```
P1_Last → P1_Current
P2_Last → P2_Current
P3_Last → P3_Current
```

进行 Sphere Sweep。

例如：

```
SweepSingleByChannel()
```

或者：

```
SphereTrace
```

于是实际检测空间类似：

```
上一帧

   O

移动路径

   O================O

                   当前帧
```

这样就不会因为高速移动而漏判。

### 面试可能直接问：

> 为什么动作游戏攻击判定喜欢 Sweep 而不是 Overlap？

你可以回答：

**Overlap 只检查当前时刻的空间重叠，而 Sweep 会检测从上一位置到当前位置之间扫过的空间，因此高速武器或角色移动时更不容易发生 tunneling（穿透 / 漏判）。**

这是非常典型的战斗开发问题。

# 3. 离散碰撞 vs 连续碰撞 CCD

这也是经典物理面试题。


只检测：

```

```

这些时间点。

如果物体移动：

```

Bullet
  O
```

这叫：

> 战斗判定通常需要更强的可控性。

# 4. Raycast 和 Sweep 的区别

非常可能问。

Raycast：

```
一条线

-------------------->
```

没有体积。

Sphere Sweep：

```
    ______
  /        \
 O----------O
  \________/
```

有半径。

因此攻击判定通常：

```
Raycast
```

可能太严格。

例如剑：

```
实际刀刃：

========

--------
```

玩家看到明明砍中了，但射线可能没碰到。

因此动作游戏经常：

```
Sphere Trace
Capsule Trace
Box Trace
```

而不是纯 Line Trace。

这关系到一个战斗系统里非常重要的概念：

> **判定宽容度。**

例如视觉刀刃宽度：

```
5cm
```

实际判定可能：

```
10cm
```

提升手感。

# 7. 点、球、AABB 的基本碰撞数学

战斗开发岗有时候会让你现场写。

例如：

> 判断两个球是否碰撞。

```
bool IsSphereOverlap(
    FVector A,
    float RadiusA,
    FVector B,
    float RadiusB)
{
    float DistanceSq = FVector::DistSquared(A, B);
    float Radius = RadiusA + RadiusB;

    return DistanceSq <= Radius * Radius;
}
```

注意：

不要：

```
sqrt()
```

因为：

```
sqrt 比平方比较更贵
```

所以：

```
distanceSquared < radiusSquared
```

是常见优化。

# 8. 点到线段最近点

这个我非常建议你掌握。

因为：

```
Capsule
```

的很多碰撞计算，本质上就是：

> 点到线段距离。

比如胶囊：

```
       O
       |
       |
       |
       O
```

可以理解成：

```
线段 + radius
```

判断球和 Capsule 是否碰撞：

```
求球心 P
到 Capsule 中轴线 AB
最近点 Q
```

然后：

```
|P-Q|
<
SphereRadius + CapsuleRadius
```

---

## 最近点公式

线段：

```
A -------- B
```

点：

```
       P
```

计算：

```
AB = B - A
AP = P - A

t = dot(AP, AB) / dot(AB, AB)
```

然后 clamp：

```
t = clamp(t, 0, 1)
```

最近点：

```
Q = A + t * AB
```

这是游戏数学 + 物理非常常见的一道题。

# 17. 同一攻击为什么不能重复伤害

```

```

```

```


# 28. 格挡也可能问物理

比如：

> 怎么判断怪物攻击是不是从玩家正面打来的？

角色 Forward：

```
F
```

攻击来源：

```
Enemy → Player
```

得到方向：

```
AttackDir = Normalize(EnemyPos - PlayerPos);
```

然后：

```
Dot = Dot(PlayerForward, AttackDir);
```

如果：

```
Dot > cos(BlockAngle)
```

说明在格挡范围内。

例如：

```
格挡角度 ±60°
```

总范围：

```
120°
```

判断：

```
dot > cos(60°)
```

然后再结合：

```
HitBox
BlockState
AttackType
```

判断是否格挡。

所以动作游戏里的：

```
向量数学
```

其实经常和物理系统绑在一起。

# 30. 不过战斗开发最好至少知道 SAT 是什么

Separating Axis Theorem：

```
分离轴定理
```

核心思想：

> 如果两个凸多边形存在一个轴，使它们在该轴上的投影不重叠，那么两个物体一定没有碰撞。

例如：

```
Box A

   +----+
   |    |
   +----+

             +----+
             | B  |
             +----+
```

找某个轴：

```
------------->
```

投影：

```
AAAA

          BBBB
```

不重叠：

```
No Collision
```

SAT 常用于：

```
OBB
Convex Polygon
```

的碰撞判断。
