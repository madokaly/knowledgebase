<img width="737" height="1131" alt="image" src="https://github.com/user-attachments/assets/e2ee3282-5dec-44c0-a65d-776455390c26" /># **动画重定向（Animation Retargeting）原理详解及高频面试题**

动画重定向（Animation Retargeting）是游戏骨骼动画系统中的核心技术之一，主要用于解决**不同骨骼结构、不同身体比例的角色之间，如何复用同一套动画资源**的问题。

结合 UE5 游戏客户端开发，以及鸣潮这类动作游戏的开发场景，重点讲解以下内容：骨骼变换原理、旋转重定向、位移重定向、参考姿势校正、FK 与 IK 重定向、UE5 IK Retargeter、Root Motion（根运动）以及常见面试问题。

# **一、什么是动画重定向**

假设游戏中有三个不同体型的角色：

<img width="731" height="530" alt="image" src="https://github.com/user-attachments/assets/2c15f3b8-521f-427d-83d5-84eddbcc590e" />

角色 A 拥有一套完整的动画资源，包括：

- Idle（待机）
- Run（跑步）
- Jump（跳跃）
- Attack（攻击）
- Dodge（闪避）
- Hit Reaction（受击）
- Death（死亡）

角色 B 和角色 C 的身高、手臂长度、腿部长度、骨骼数量甚至骨骼命名都可能与角色 A 不同。

如果每个角色都重新制作一套动画，那么动画制作成本、资源存储成本和后期维护成本都会非常高。

动画重定向就是将源角色的动画运动信息转换到目标角色的骨骼上，使目标角色能够正确地播放相同的动作。

|名词|中文解释|
|---|---|
|Source Skeleton|源骨骼，提供原始动画|
|Target Skeleton|目标骨骼，接收动画|
|Reference Pose|参考姿势，骨骼的基础姿势|
|Retarget Pose|重定向姿势，用于对齐源和目标的姿势|
|Bone Mapping|骨骼映射，建立骨骼对应关系|
|Chain Mapping|骨骼链映射，建立肢体链对应关系|
|FK Retargeting|正向运动学重定向|
|IK Retargeting|逆向运动学重定向|
|Root Motion|根运动，动画产生的角色整体位移与旋转|

# **二、为什么不能直接复用骨骼动画**

要理解动画重定向，首先需要理解骨骼动画存储的是什么。

## **2.1 骨骼动画的本质**

骨骼动画本质上记录的是各个骨骼随时间变化的变换信息（Transform）。

每个骨骼通常包含三个属性：

```
struct BoneTransform
{
    FVector Translation;  // 位移，相对于父骨骼
    FQuat   Rotation;     // 旋转，通常使用四元数表示
    FVector Scale;        // 缩放
};
```

例如一个手臂骨骼层级：

<img width="726" height="391" alt="image" src="https://github.com/user-attachments/assets/114e2c36-62f7-46db-b68f-fbc01dfb76d3" />

假设骨骼层级如下：

```
Root                 // 根骨骼
 └─ Pelvis           // 骨盆
     └─ Spine        // 脊柱
         └─ Clavicle // 锁骨
             └─ UpperArm  // 上臂
                 └─ LowerArm  // 前臂
                     └─ Hand  // 手部
```

子骨骼的全局变换需要通过父骨骼逐级计算。

采用列向量矩阵约定：

$$
M_{global}^{i}=M_{global}^{parent}M_{local}^{i}
$$

其中：

$$
M_{local}^{i}：当前骨骼相对于父骨骼的局部变换。
$$
$$
M_{global}^{parent}：父骨骼在骨骼模型空间中的累计变换。
$$
$$
M_{global}^{i}：当前骨骼在骨骼模型空间中的累计变换。
$$

这里的 Global 指骨架内部的全局空间，对应 UE 中的 Component Space（组件空间），不一定是游戏世界坐标系。

UE 的 `FTransform` 乘法书写顺序与上述列向量矩阵约定不同，实际编程时需要注意。

## **2.2 直接复制骨骼位移的问题**

假设两个角色的手臂长度不同。

<img width="727" height="372" alt="image" src="https://github.com/user-attachments/assets/b9fc6178-b599-418c-be08-1d0c5d5ac3c8" />

|骨骼长度|源角色 A|目标角色 B|
|---|---|---|
|上臂|50 cm|70 cm|
|前臂|40 cm|60 cm|
|总长度|90 cm|130 cm|

如果直接将源角色的骨骼局部位移复制到目标角色，那么目标角色的骨骼长度可能会被改变，造成：

- 手臂或者腿部缩短、拉长。
- 蒙皮网格异常变形。
- 肩膀、膝盖等关节错位。
- 手部无法正确握住武器。
- 角色出现脚部滑动、悬空或穿地。

因此，动画重定向的一个基本原则是：

**尽量传递源角色的运动信息，同时保留目标角色自身的骨骼结构与身体比例。**

## **2.3 直接复制骨骼旋转的问题**

不同角色的骨骼局部坐标轴、参考姿势也可能不同。

例如：

<img width="754" height="399" alt="image" src="https://github.com/user-attachments/assets/f81efdee-36f3-4187-aed6-f26dfb06aa7d" />

假设源角色是 T-Pose，目标角色是 A-Pose，两者的上臂参考方向相差 40°。

即使直接复制相同的局部旋转值，也不一定会得到相同的实际动作。

此外，还可能存在：

- 源骨骼沿 X 轴指向子骨骼，目标骨骼沿 Y 轴指向子骨骼。
- 骨骼局部坐标轴存在不同程度的扭转。
- 源角色与目标角色的父子层级不同。
- 两个角色拥有不同数量的脊柱或扭转骨骼。

这些问题都需要进行参考姿势校正、坐标空间转换或骨骼链重定向。

# **四、骨骼映射（Bone Mapping）**

## **4.1 一对一骨骼映射**

首先需要确定源角色的哪根骨骼对应目标角色的哪根骨骼。

例如两个角色的骨骼命名完全不同：

|源角色骨骼|目标角色骨骼|中文含义|
|---|---|---|
|root|RootNode|根骨骼|
|pelvis|Hips|骨盆|
|spine_01|Spine|脊柱|
|upperarm_l|LeftArm|左上臂|
|lowerarm_l|LeftForeArm|左前臂|
|hand_l|LeftHand|左手|
|thigh_l|LeftUpLeg|左大腿|
|calf_l|LeftLeg|左小腿|
|foot_l|LeftFoot|左脚|

底层可以通过映射表保存对应关系。

```
// Key：源骨骼索引
// Value：目标骨骼索引
TMap<int32, int32> BoneMapping;
```

运行时通常会提前缓存骨骼索引，避免每帧通过字符串查找骨骼。

但是，一对一映射有一个明显的问题：如果两个角色的骨骼数量不同，该如何对应？

## **4.2 骨骼链映射（Chain Mapping）**

假设两个角色的脊柱骨骼数量不同。

<img width="736" height="565" alt="image" src="https://github.com/user-attachments/assets/292b9a33-6664-4aec-aa88-92e7ad0989c0" />

UE5 的 IK Retargeter 可以使用骨骼链作为映射单位，因此源角色和目标角色不必具有完全相同的骨骼数量。

例如：

```
Source Chain：Spine
    Start Bone：spine_01
    End Bone：spine_03

Target Chain：Spine
    Start Bone：spine_01
    End Bone：spine_05
```

一种常用的链映射思路，是将骨骼链的位置归一化到 0～1 的范围。

|源骨骼链参数|目标骨骼链参数|
|---|---|
|Bone 0：0.0|Bone 0：0.0|
|Bone 1：0.5|Bone 1：0.25|
|Bone 2：1.0|Bone 2：0.5|
|—|Bone 3：0.75|
|—|Bone 4：1.0|

目标骨骼可以根据归一化参数，从源链的姿势信息中进行采样和插值。旋转通常使用四元数插值，并结合参考姿势和父子关系计算。

这样即使骨骼数量不一致，也能较好地传递脊柱的弯曲、旋转等运动。

# **五、旋转重定向（Rotation Retargeting）**

这是动画重定向最核心的原理之一。

## **5.1 提取相对于参考姿势的旋转变化量**

动画重定向真正需要传递的，通常不是源骨骼的绝对旋转，而是源骨骼相对于基础姿势发生了怎样的运动。

假设：

- 源角色的上臂参考姿势：0°。
- 源角色的上臂当前动画旋转：60°。
- 目标角色的上臂参考姿势：-30°。

在旋转轴一致、以各自参考姿势为动作零点的简化情况下：

$$
\Delta R=60°-0°=60°
$$

目标骨骼旋转为：

$$
R_{target}=-30°+60°=30°
$$

<img width="740" height="636" alt="image" src="https://github.com/user-attachments/assets/355542e3-fdb8-43a6-967e-61c09014d1b5" />

注意：实际重定向通常还会先对齐 Retarget Pose。如果目标需要与源角色保持相同的绝对肢体朝向，就不能只保留原始参考姿势偏移。

## **5.2 四元数旋转重定向公式**

三维空间中，不能简单地通过欧拉角相减获得旋转差值，因为旋转具有顺序依赖性，并且可能产生万向节锁问题。

因此通常使用 Quaternion（四元数）。

定义：

$$
Q_s^{ref}，源骨骼参考旋转
$$

$$
Q_s^{anim}，源骨骼当前动画旋转
$$

$$
Q_t^{ref}，目标骨骼参考旋转
$$

$$
\Delta Q_s，源骨骼的局部相对旋转
$$

$$
Q_t^{anim}，重定向后的目标旋转
$$

首先计算源骨骼相对于参考姿势的旋转变化量：

$$
\boxed{\Delta Q_s=(Q_s^{ref})^{-1}Q_s^{anim}}
$$

如果源和目标的运动坐标轴已经对齐，则可以将变化量应用到目标骨骼：

$$
\boxed{Q_t^{anim}=Q_t^{ref}\Delta Q_s}
$$

对应的 UE C++ 原理示例：

```
FQuat RetargetRotation(
    const FQuat& SourceRefRotation,   // 源参考旋转
    const FQuat& SourceAnimRotation,  // 源动画旋转
    const FQuat& TargetRefRotation)   // 目标参考旋转
{
    // 1. 提取源骨骼相对于参考姿势的旋转变化
    FQuat DeltaRotation =
        SourceRefRotation.Inverse() * SourceAnimRotation;

    // 2. 将旋转变化应用到目标参考姿势
    FQuat TargetRotation =
        TargetRefRotation * DeltaRotation;

    // 3. 归一化，避免浮点误差累积
    return TargetRotation.GetNormalized();
}
```

上述代码是假设骨骼运动坐标轴已经对齐的简化实现，并不是 UE5 IK Retargeter 的完整源码。

## **5.3 骨骼坐标轴不一致怎么办**

假设源角色绕局部 Z 轴旋转表示弯曲手肘，而目标角色绕局部 X 轴旋转才表示弯曲手肘。

<img width="744" height="407" alt="image" src="https://github.com/user-attachments/assets/4935938f-e7b4-4c51-9e54-c0e07afb8167" />

此时必须进行坐标空间转换。

假设 \(C\) 是将源骨骼运动坐标系中的向量转换到目标骨骼运动坐标系的旋转，则：

$$
\Delta Q_t=C\Delta Q_sC^{-1}
$$

最终得到：

$$
\boxed{Q_t^{anim}=Q_t^{ref}C\Delta Q_sC^{-1}}
$$

这就是旋转的 Change of Basis（基变换）。

```
// 将源骨骼的旋转变化转换到目标骨骼坐标系
FQuat TargetDelta =
    BasisCorrection *
    SourceDelta *
    BasisCorrection.Inverse();

// 应用到目标参考旋转
FQuat TargetRotation =
    TargetRefRotation * TargetDelta;
```

实际工程中，可以通过对齐后的参考姿势、骨骼方向以及组件空间变换来建立这种坐标系对应关系。

如果忽略坐标轴差异，就可能出现：

- 手臂旋转 90°。
- 手腕翻转。
- 膝盖反向弯曲。
- 肩膀异常扭曲。
- 角色肢体发生 180° 翻转。

# **六、位移重定向（Translation Retargeting）**

骨骼旋转决定肢体如何运动，而局部位移通常决定骨骼关节之间的距离。

UE 的传统 Skeleton Translation Retargeting（骨架位移重定向）提供了以下模式。

Epic Developer Community+1

|模式|中文解释|
|---|---|
|Animation|直接使用动画位移|
|Skeleton|使用目标骨架的参考位移|
|AnimationScaled|根据骨骼比例缩放动画位移|
|AnimationRelative|根据参考姿势差异进行相对调整|
|OrientAndScale|根据参考方向和长度调整位移|

前三种是面试中最常问、最需要掌握的。

## **6.1 Animation（动画位移）**

直接使用源动画记录的局部位移。

$$
T_t=T_s^{anim}
$$

例如源动画骨骼位移为 50 cm，目标骨骼参考位移为 70 cm，最终使用的就是 50 cm。

```
TargetTranslation = SourceAnimTranslation;
```

适用场景：

- Root Bone（根骨骼）。
- 武器辅助骨骼。
- 部分 IK 标记骨骼。
- 需要保留原始动画位移的骨骼。

缺点是可能破坏目标角色自身的身体比例。

## **6.2 Skeleton（骨架位移）**

忽略动画中的骨骼位移，直接使用目标骨骼的参考姿势位移。

$$
T_t=T_t^{ref}
$$

```
TargetTranslation = TargetRefTranslation;
```

假设源角色的前臂长度为 40 cm，目标角色的前臂长度为 60 cm，那么目标角色仍然保留 60 cm 的前臂长度。

适用于大部分依靠旋转驱动的肢体骨骼。

优点是能保持角色原有体型，缺点是会丢弃该骨骼动画轨道中的位移动画。

## **6.3 AnimationScaled（动画位移缩放）**

根据目标骨骼与源骨骼的参考位移长度比例，对动画位移进行缩放。

$$
ScaleRatio= \frac{|T_t^{ref}|}{|T_s^{ref}|}
$$

$$
\boxed{T_t=T_s^{anim}\times ScaleRatio}
$$

例如源角色骨盆参考高度为 100 cm，目标角色为 150 cm。

当源角色下蹲，骨盆高度从 100 cm 变成 80 cm 时：

$$
ScaleRatio=\frac{150}{100}=1.5
$$

$$
T_t=80\times1.5=120\text{ cm}
$$

<img width="738" height="812" alt="image" src="https://github.com/user-attachments/assets/2c47c3b6-250d-4c05-bd4d-ee0c970fef37" />

对应的 C++ 原理：

```
float SourceLength = SourceRefTranslation.Size();
float TargetLength = TargetRefTranslation.Size();

// 防止除以零
float Ratio = SourceLength > KINDA_SMALL_NUMBER
    ? TargetLength / SourceLength
    : 1.0f;

// 根据目标骨骼比例调整动画位移
FVector TargetTranslation =
    SourceAnimTranslation * Ratio;
```

## **6.4 UE 传统重定向常用设置**

|骨骼类型|推荐的初始设置|原因|
|---|---|---|
|Root（根骨骼）|Animation|保留根骨骼运动|
|Pelvis（骨盆）|AnimationScaled|根据体型调整高度|
|Spine（脊柱）|Skeleton|保留身体比例|
|UpperArm（上臂）|Skeleton|保留肢体长度|
|LowerArm（前臂）|Skeleton|保留肢体长度|
|Thigh（大腿）|Skeleton|保留腿部长度|
|Calf（小腿）|Skeleton|保留腿部长度|
|IK Bones（IK 辅助骨骼）|Animation|保留动画标记位置|
|Weapon Bone（武器骨骼）|Animation|保留武器动画信息|

这是传统人形骨架的一种常用配置，并不意味着所有项目都应该使用这套设置。

尤其要注意：

**UE 传统的 Translation Retargeting 设置主要处理骨骼位移，而 UE5 IK Retargeter 是另一套更完整的动画重定向机制。**

不要将两套系统的设置混为一谈。

# **七、FK 重定向（Forward Kinematics）**

## **7.1 什么是 FK**

FK（Forward Kinematics，正向运动学）是指已知各个关节的旋转、位移，通过骨骼父子层级计算末端骨骼的位置。

例如：

```
已知肩膀旋转
    ↓
计算肘关节位置
    ↓
已知肘关节旋转
    ↓
计算手腕位置
```

对于一个二维手臂：

$$
x=L_1\cos\theta_1+L_2\cos(\theta_1+\theta_2)
$$

$$
y=L_1\sin\theta_1+L_2\sin(\theta_1+\theta_2)
$$

其中：

$$
L_1：上臂长度。
$$
$$
L_2：前臂长度。
$$
$$
\theta_1：肩关节旋转角度。
$$
$$
\theta_2：肘关节相对旋转角度。
$$
$$
x,y：最终手部位置。
$$

FK 重定向主要关注源角色各个关节的旋转变化和骨骼链的运动形态，并将其传递给目标角色。

## **7.2 FK 重定向存在的问题**

假设源角色和目标角色的手臂长度不同，但保持相同的旋转角度。

<img width="684" height="521" alt="image" src="https://github.com/user-attachments/assets/44d778c6-5cd9-4411-8b5b-24539c56b75f" />

尽管两个角色的关节旋转角度完全一致，但是由于目标角色手臂更长，其手部位置就可能超过原本的武器握持点。

同样的问题也会出现在：

- 双手持剑时，副手无法握住剑柄。
- 弓箭角色拉弓时，手部位置错误。
- 双脚踩在地面上的位置不一致。
- 攀爬时，手部无法抓住墙壁。
- 双人交互动画出现接触位置偏差。

这就是为什么单纯的 FK 重定向通常无法满足高质量动作游戏的所有需求。

# **八、IK 重定向（Inverse Kinematics）**

## **8.1 什么是 IK**

IK（Inverse Kinematics，逆向运动学）与 FK 的计算方向相反。

FK 是已知关节旋转，求末端位置。

IK 是已知末端目标位置，反向求解各个关节的旋转，使末端尽可能到达指定位置。

<img width="739" height="387" alt="image" src="https://github.com/user-attachments/assets/d8e6368c-5c83-4284-bfca-fd97b8499ebb" />

在动画重定向中，可以先通过 FK 得到目标角色的初始姿势，再通过 IK 调整手部和脚部。

## **8.2 Two Bone IK（双骨骼逆向运动学）原理**

Two Bone IK 是游戏中非常常用的 IK 算法，适用于手臂和腿部。

以手臂为例：

```
Shoulder（肩膀）
    ↓ 上臂长度 L1
Elbow（肘关节）
    ↓ 前臂长度 L2
Hand（手部）
```

已知肩膀位置、手部目标位置，以及上臂和前臂长度。

就可以通过三角形余弦定理求解肘关节角度。

假设肩膀到手部目标位置的距离为 \(d\)。

$$
d=|P_{goal}-P_{shoulder}|
$$

肘关节内部夹角为：

$$
\cos\beta= \frac{L_1^2+L_2^2-d^2}{2L_1L_2}
$$

$$
\beta=\arccos \left( \frac{L_1^2+L_2^2-d^2}{2L_1L_2} \right)
$$

如果用手臂伸直时为 0° 的关节弯曲角表示，则：

$$
\theta_{elbow}=\pi-\beta
$$

肩关节相对于目标连线的夹角也可以通过余弦定理计算。

在三维空间中，还需要确定肘关节朝哪个方向弯曲，这就需要 Pole Vector（极向量）或者 Joint Target（关节方向目标）。

## **8.3 Two Bone IK 交互演示**

<img width="737" height="1131" alt="image" src="https://github.com/user-attachments/assets/17eacbd1-eaf6-41c1-9bec-c026564f84f3" />

可以通过调整上臂和前臂长度观察：即使角色体型发生变化，IK 仍然能够通过改变关节角度，让手部到达同一个目标位置。

如果目标距离超过两根骨骼的总长度，则在不允许骨骼拉伸的情况下，只能到达最接近目标的可达位置。

## **8.4 常用 IK 求解算法**

|算法|中文名称|实现原理|适用场景|
|---|---|---|---|
|Two Bone IK|双骨骼 IK|三角函数解析求解|手臂、腿部|
|CCD IK|循环坐标下降 IK|逐个旋转关节，迭代逼近目标|多关节肢体|
|FABRIK|前向后向迭代 IK|反复调整关节位置，保持骨骼长度|长骨骼链、尾巴|
|Full Body IK|全身 IK|综合求解多末端及全身约束|全身姿态、多点接触|

Two Bone IK 通常不需要多轮迭代，计算开销较低，是手臂和腿部非常常见的求解方式。

## **8.5 FK 与 IK 的区别**

|对比项|FK|IK|
|---|---|---|
|中文名称|正向运动学|逆向运动学|
|输入|关节变换|末端目标及约束|
|输出|末端姿势|关节姿势|
|核心目标|保留动作形态|保证目标接触|
|计算方式|层级变换|解析或迭代求解|
|性能开销|通常较低|与求解器复杂度有关|
|动作自然程度|较好地保留原始动画|依赖关节约束和初始姿势|
|典型场景|跑步、挥砍、受击|脚部贴地、抓取、武器握持|

**实际游戏中通常不是 FK 和 IK 二选一，而是先利用 FK 保留原始动画，再使用 IK 对关键部位进行修正。**

# **九、Root Motion（根运动）重定向**

Root Motion 指从动画根骨骼运动中提取角色的整体位移和旋转，并由角色移动系统应用到角色本身。

例如攻击动画中的向前突进、闪避翻滚、跳跃落地等。

## **9.1 Root 与 Pelvis 的区别**

<img width="709" height="431" alt="image" src="https://github.com/user-attachments/assets/32800cea-a54a-439d-94cf-045a0e2c01ec" />

|对比项|Root|Pelvis|
|---|---|---|
|中文名称|根骨骼|骨盆|
|通常位置|地面附近|身体髋部|
|主要用途|整体移动、旋转|身体高度、重心运动|
|下蹲时|可能保持不变|向下移动|
|攻击突进时|可提供前进位移|相对于根骨骼运动|

UE5 IK Retargeter 中用于重定向身体运动的根节点概念，与 Root Motion 提取所使用的实际根骨骼并不一定是同一根骨骼。传统 IK Rig 工作流中，人形角色的 Retarget Root（重定向根）通常选择 Pelvis。

## **9.2 根运动应该根据体型缩放吗**

假设：

- 源角色身高为 180 cm。
- 目标角色身高为 270 cm。
- 源角色闪避动画的 Root Motion 为 300 cm。

如果根据身高比例缩放：

$$
ScaleRatio=\frac{270}{180}=1.5
$$

$$
TargetRootMotion=300\times1.5=450\text{ cm}
$$

但是在动作游戏中，这不一定合理。

因为闪避距离、攻击距离、技能突进距离通常还涉及游戏玩法规则，而不仅仅是动画表现。

|根运动策略|结果|适用场景|
|---|---|---|
|保留绝对位移|仍然移动 300 cm|固定技能移动距离|
|按角色比例缩放|移动 450 cm|自然步态、体型差异|
|按玩法指定距离调整|由技能逻辑决定|攻击、闪避、突进|
|Motion Warping|向指定目标调整运动轨迹|处决、攀爬、锁敌攻击|

对于动作游戏，通常需要将动画表现与玩法规则进行协调，而不是直接根据骨骼比例修改所有位移。

# **十、UE5 动画重定向系统详解**

UE 中主要需要掌握两套机制。

|对比项|传统 Animation Retargeting|IK Rig Retargeting|
|---|---|---|
|核心机制|骨架位移模式、旧式 Rig 映射|骨骼链映射、姿势校正和 IK|
|相同 Skeleton|支持|支持|
|不同 Skeleton|可通过旧式映射重定向|支持|
|骨骼数量差异|灵活性有限|支持骨骼链适配|
|FK 重定向|基础旋转传递及映射|支持链级配置|
|IK 末端修正|通常另行处理|可集成在重定向过程中|
|运行时跨骨架转换|能力相对有限|支持|
|常见使用场景|兼容骨架共享动画|不同骨架之间的动画转换|

UE5 的 IK Rig 系统支持离线生成新动画，也支持运行时姿势重定向。

## **10.1 UE5 核心资源和组件**

<img width="742" height="444" alt="image" src="https://github.com/user-attachments/assets/536a275f-25a3-4cd4-a6b5-d58d28848187" />

|UE 名词|主要作用|
|---|---|
|Skeletal Mesh|保存模型、蒙皮信息和参考骨架|
|Skeleton|骨架资产，维护动画关联等骨骼信息|
|IK Rig|定义骨骼链、IK 目标及求解器等|
|IK Retargeter|建立源和目标之间的运动转换关系|
|Retarget Chain|定义需要传递运动的骨骼链|
|Retarget Pose|对齐源角色与目标角色的基础姿势|
|IK Goal|手部、脚部等需要到达的目标|
|IK Solver|根据目标和约束计算骨骼姿势|

## **10.2 IK Rig 与 IK Retargeter 的区别**

这是 UE5 比较常见的面试问题。

IK Rig 关注的是单个角色自身的骨骼结构和 IK 求解配置。

IK Retargeter 关注的是两个角色之间如何转换动画。

例如：

```
IK_CharacterA
    ├─ Spine Chain
    ├─ LeftArm Chain
    ├─ RightArm Chain
    ├─ LeftLeg Chain
    └─ RightLeg Chain

IK_CharacterB
    ├─ Spine Chain
    ├─ LeftArm Chain
    ├─ RightArm Chain
    ├─ LeftLeg Chain
    └─ RightLeg Chain

RTG_A_To_B
    ├─ Source IK Rig = IK_CharacterA
    ├─ Target IK Rig = IK_CharacterB
    ├─ Chain Mapping
    ├─ Retarget Pose
    └─ Retarget Operations
```

可以将 IK Rig 理解为对角色骨架的功能性描述，将 IK Retargeter 理解为两个骨架之间的动画转换器。

## **10.3 FK Rotation Mode（FK 旋转映射模式）**

UE5 的链级 FK 重定向具有多种旋转映射方式，其中比较常见的是：

|模式|原理|
|---|---|
|Interpolated（插值）|根据链上的归一化位置采样源链旋转|
|One to One（一对一）|从骨骼链起点开始逐根对应|
|One to One Reversed（反向一对一）|从骨骼链末端开始逐根对应|
|None（不重定向旋转）|不从源链传递该部分旋转|

例如源角色有三节脊柱，而目标角色有五节脊柱，可以优先考虑 Interpolated 模式。

对于数量和层级一致的手指骨骼，则可以考虑 One to One。

## **10.4 UE5 重定向资源制作流程**

典型工作流程为：创建源和目标的 IK Rig，定义身体各部分的骨骼链，创建 IK Retargeter，建立链对应关系，校准 Retarget Pose，调整 FK、IK、骨盆和根运动相关设置，最后进行动画预览与导出。

不同 UE5 小版本的编辑器界面和配置位置存在差异。例如 UE5.8 文档中的 Retarget Operation Stack（重定向操作栈）允许组合、排序不同重定向操作，并配置相应的 LOD 阈值。

# **十一、离线重定向与运行时重定向**

## **11.1 Offline Retargeting（离线重定向）**

在编辑器中提前完成重定向，将结果保存为新的动画资源。

<img width="738" height="277" alt="image" src="https://github.com/user-attachments/assets/d66f9a49-d3a8-4834-a7c8-945bfa856fd4" />

优点是运行时不需要执行完整的跨骨架重定向求解，性能更加可控，动画师也可以继续修改生成的动画。

缺点是会增加动画资源数量和磁盘占用，源动画修改后可能需要重新批量导出。

## **11.2 Runtime Retargeting（运行时重定向）**

UE5 中可以通过动画蓝图中的 `Retarget Pose From Mesh` 等机制，实现从源 Mesh 的实时姿势转换到目标 Mesh。

<img width="740" height="262" alt="image" src="https://github.com/user-attachments/assets/f0045136-bfd0-47e8-a837-60be224c10ac" />

优点是可以减少重复的动画资产，并根据源角色的实时姿势动态更新目标角色。

缺点是增加运行时 CPU 开销，而且可能需要维护额外的源 Skeletal Mesh Component 及其动画更新。

|对比项|离线重定向|运行时重定向|
|---|---|---|
|重定向时机|编辑器|游戏运行时|
|是否生成新动画资源|是|通常不需要|
|CPU 重定向开销|提前计算|每次姿势求值时计算|
|磁盘空间占用|较高|较低|
|动画人工修正|方便|相对复杂|
|灵活性|较低|较高|
|适用场景|固定角色、固定动作|动态角色、UGC、实时姿势转换|

对于角色数量较多的商业动作游戏，可以优先考虑兼容骨架共享动画，其次考虑离线重定向，对于确实需要动态跨骨架转换的场景再使用运行时重定向。

# **十二、动画重定向与 Foot IK（脚部 IK）**

## **12.1 为什么重定向之后仍然会出现脚滑**

假设源角色的跑步动画每一步跨越 100 cm，但目标角色腿更长，经过重定向后每一步自然跨越 150 cm。

如果角色移动系统仍然按照原来的移动速度驱动角色，那么动画步幅与角色实际位移就不匹配。

<img width="709" height="394" alt="image" src="https://github.com/user-attachments/assets/a9737c59-ad45-41c9-abb4-84dc404c9ca8" />

脚滑（Foot Sliding）通常是角色移动速度、动画播放速度、步幅以及脚部接触状态不一致导致的。

仅仅使用骨骼重定向不能完全解决脚滑。

## **12.2 常用解决方案**

|技术|中文解释|解决的问题|
|---|---|---|
|Foot IK|脚部逆向运动学|脚部悬空、穿地|
|Foot Locking|脚部锁定|支撑脚在接触阶段滑动|
|Stride Warping|步幅扭曲|动画步幅与移动速度不匹配|
|Speed Matching|速度匹配|根据移动速度调整动画播放速度|
|Distance Matching|距离匹配|停步、起步、落地距离不准确|
|Speed Planting|基于速度的末端锁定|重定向过程中脚部滑动|
|Motion Warping|运动扭曲|根运动轨迹与目标位置不匹配|

### **Foot Locking 原理**

当检测到脚部进入支撑阶段（Plant Phase）时，记录脚部在世界空间中的接触位置。

```
// 脚部刚接触地面
if (bEnterFootPlant)
{
    // 记录世界空间中的脚部位置
    LockedFootWorldPosition = CurrentFootWorldPosition;
}

// 脚部处于支撑阶段
if (bFootPlanted)
{
    // 将锁定位置转换到 Mesh 组件空间
    FVector IKTargetPosition =
        MeshWorldTransform.InverseTransformPosition(
            LockedFootWorldPosition
        );

    // 将该位置提供给脚部 IK 求解器
}
```

即使角色根节点向前移动，脚部 IK 也会尽可能保持脚掌处于原来的世界空间位置。

直到脚部进入抬脚阶段，再逐渐解除锁定。

如果脚部站在移动平台上，通常需要相对于平台记录锁定位置，而不是简单地固定在世界坐标系中。

### **Stride Warping 原理**

根据实际移动速度和动画对应的原始移动速度，调整步幅。

$$
StrideScale= \frac{CharacterMoveSpeed}{AnimationMoveSpeed}
$$

假设：

- 角色实际速度：450 cm/s。
- 动画对应速度：300 cm/s。

则：

$$
StrideScale=\frac{450}{300}=1.5
$$

在保持骨骼长度的前提下，可以调整脚部目标位置，再通过 IK 求解腿部姿势，让步幅与实际移动速度更加匹配。

实际实现还需要考虑速度方向、步态切换、骨盆调整和最大可达距离。

# **十三、动作游戏中动画重定向的工程应用**

以鸣潮类多角色动作游戏为例，以下是通用的工程设计方案，并不代表鸣潮实际使用的内部实现。

## **13.1 按角色类型建立标准骨架**

```
Humanoid_Skeleton
│
├─ Male_Type_A      // 标准男性体型
├─ Female_Type_A    // 标准女性体型
├─ Tall_Type        // 高大体型
└─ Small_Type       // 矮小体型

Monster_Skeleton
│
├─ HumanoidMonster  // 人形怪物
├─ Quadruped        // 四足怪物
└─ GiantBoss        // 巨型 Boss
```

尽量统一核心骨骼的命名、层级、参考姿势和坐标轴方向。

这样可以减少动画重定向的复杂度，也有利于统一：

- 武器挂点（Socket）。
- 战斗碰撞检测。
- 动画通知（Anim Notify）。
- 动画蓝图（Anim Blueprint）。
- Control Rig（控制绑定）。
- IK 求解和物理骨骼配置。

## **13.2 区分共享动画与角色专属动画**

|动画类型|推荐方案|
|---|---|
|通用待机|共享或重定向|
|通用跑步|共享或重定向，并修正步态|
|通用跳跃|共享或重定向|
|基础受击|共享或重定向|
|通用死亡|共享或重定向|
|专属普攻|独立制作或精修重定向结果|
|专属技能|独立制作或精修|
|双人处决|专门调整双方接触关系|
|特殊武器攻击|根据武器和角色体型制作|

动画重定向是降低制作成本的技术，不应该以牺牲角色动作特色和战斗表现为代价。

## **13.3 动画重定向对攻击碰撞检测的影响**

这是动作类游戏客户端开发中非常值得关注的问题。

假设源角色使用长剑进行横向挥砍，目标角色经过重定向后，由于手臂更长、肩膀旋转存在差异，武器挥动轨迹也会发生变化。

<img width="695" height="414" alt="image" src="https://github.com/user-attachments/assets/b1f40cd8-b2f8-44b8-b91f-5e6433152d57" />

如果攻击判定仍然使用源角色的武器轨迹，就可能出现：

- 玩家看到武器已经击中敌人，但没有造成伤害。
- 武器明明没有碰到敌人，却触发了伤害。
- 不同体型角色的攻击距离不一致。
- 客户端与服务器的攻击判定不一致。

常见的工程处理方式：

**方案一：基于实际武器 Socket 进行碰撞检测。**

从最终动画姿势中读取武器起点和终点 Socket，使用 Sweep（扫掠检测）计算攻击轨迹。

```
FVector WeaponStart =
    Mesh->GetSocketLocation(TEXT("Weapon_Start"));

FVector WeaponEnd =
    Mesh->GetSocketLocation(TEXT("Weapon_End"));

// 记录上一帧与当前帧的武器位置
// 使用 Sphere Trace / Capsule Trace 等
// 检测武器运动过程中经过的空间
```

这种方案视觉一致性较好，但需要处理动画更新时序、低帧率漏检、重复命中等问题。

**方案二：使用独立的攻击判定配置。**

在技能数据中定义 HitBox（攻击判定体）、判定距离、角度和生效时间，不完全依赖实时渲染骨骼。

这种方案便于控制玩法平衡，也更加适合服务器权威判定。

**方案三：离线烘焙攻击轨迹。**

针对最终使用的角色动画，提前采样武器或者攻击骨骼的运动轨迹，生成战斗逻辑使用的数据。

服务器不必运行完整的动画蓝图和 IK，也可以根据动画时间查询攻击轨迹。

在多人动作游戏中，应该明确最终的权威攻击姿势来源，不能直接将客户端仅用于视觉修正的 IK 姿势作为服务器伤害判定依据。

# **十四、动画重定向性能优化**

动画重定向本身通常属于 CPU 动画姿势求值的一部分，不要将它与 GPU Skinning（GPU 蒙皮）混淆。

## **14.1 性能开销来源**

假设骨骼数量为 \(N\)，IK 求解涉及的关节数量为 \(K\)，迭代次数为 \(I\)。

|操作|典型复杂度|
|---|---|
|骨骼层级变换|O(N)|
|一对一骨骼映射|O(N)|
|参考姿势偏移计算|O(N)，可预计算|
|双骨骼 IK|单条链 O(1)|
|CCD / FABRIK|通常约 O(K × I)|
|全身 IK|取决于关节、约束数量和求解算法|

这些是简化后的算法复杂度，不代表 UE 实际执行耗时。

## **14.2 常用优化方案**

|优化方式|实现原理|
|---|---|
|优先使用统一骨架|减少完整跨骨架重定向需求|
|Offline Retargeting|提前烘焙重定向结果|
|Cache Bone Mapping|缓存骨骼索引映射|
|Cache Reference Transform|缓存参考姿势变换|
|Cache Basis Correction|提前计算坐标系转换关系|
|Animation LOD|远距离角色降低重定向精度|
|Disable IK by LOD|远距离角色关闭非必要 IK|
|Reduce Solver Iterations|减少 IK 求解迭代次数|
|Animation Budget Allocator|根据角色重要程度分配动画更新预算|
|Update Rate Optimization|降低非重要角色的动画更新频率|
|Parallel Animation Evaluation|利用 UE 支持的并行动画求值机制|

例如不同距离角色可以使用不同等级的动画求解方案：

|角色等级|重定向方案|
|---|---|
|LOD 0：玩家自身|完整 FK、手部 IK、脚部 IK|
|LOD 1：附近队友|FK、必要的手部和脚部 IK|
|LOD 2：远处角色|FK，关闭部分 IK|
|LOD 3：极远角色|简化姿势求值、降低更新频率|

具体哪些骨骼和 IK 可以关闭，需要结合玩法判定需求，不能单纯根据渲染距离裁剪服务器权威逻辑。

# **十五、动画重定向常见问题及解决方案**

|常见问题|主要原因|解决方案|
|---|---|---|
|手臂旋转错误|骨骼坐标轴不同|坐标空间转换、姿势校正|
|肩膀向上耸起|A-Pose 和 T-Pose 不匹配|调整 Retarget Pose|
|骨骼被拉长|直接复制源骨骼位移|保留目标骨骼参考位移|
|双脚悬空|骨盆高度不匹配|骨盆调整、Foot IK|
|脚部穿地|末端位置不准确|地面检测、Foot IK|
|跑步脚滑|移动速度与动画步幅不一致|Stride Warping、Foot Locking|
|膝盖反向弯曲|弯曲平面或者 IK 约束错误|Pole Vector、关节限制|
|双手持剑错位|手臂长度差异|副手 IK|
|脊柱弯曲异常|骨骼数量、链映射不匹配|Chain Mapping|
|手腕扭曲|局部轴向或扭转骨骼差异|轴向校正、Twist Bone 调整|
|攻击位移异常|Root Motion 缩放错误|根运动单独配置|
|武器穿模|体型及武器挂点差异|Socket 偏移、IK、人工修正|

# **十六、动画重定向高频面试题及答案**

以下按照 UE 游戏客户端、动作系统开发方向，优先整理核心原理和常见工程问题。

## **面试题 1：什么是动画重定向？为什么需要动画重定向？**

**重要程度：★★★★★**

动画重定向是将源角色的骨骼运动信息转换到目标角色骨架上的过程，使具有不同骨骼结构和身体比例的角色能够复用动画。

主要解决骨骼命名、骨骼数量、骨骼长度、参考姿势和局部坐标轴差异等问题。

其核心目的是降低动画制作成本，同时尽可能保留原始动作表现和目标角色的身体结构。

## **面试题 2：为什么不能直接复制骨骼的 Transform？**

**重要程度：★★★★★**

因为骨骼 Transform 通常是相对于父骨骼的局部变换。

如果源和目标的骨骼长度、坐标轴方向、参考姿势、父子层级不同，直接复制可能造成骨骼缩放异常、旋转错误和肢体接触位置偏差。

正确的方式通常是提取相对于参考姿势的运动变化，进行坐标空间转换，保留目标角色的骨骼长度，并根据需要进行 IK 修正。

## **面试题 3：动画重定向的旋转转换原理是什么？**

**重要程度：★★★★★**

首先计算源骨骼相对于参考姿势的旋转变化量：

$$
\Delta Q_s=(Q_s^{ref})^{-1}Q_s^{anim}
$$

在源和目标运动坐标轴已经对齐时：

$$
Q_t^{anim}=Q_t^{ref}\Delta Q_s
$$

如果坐标轴不同，还需要进行基变换。

$$
Q_t^{anim}=Q_t^{ref}C\Delta Q_sC^{-1}
$$

实际三维旋转一般使用四元数，而不是直接对欧拉角进行加减。

## **面试题 4：动画重定向为什么通常需要保留目标骨骼位移？**

**重要程度：★★★★★**

因为大多数骨骼的局部参考位移决定了关节之间的距离。

直接复制源骨骼位移，会改变目标角色的骨骼长度，进而造成模型变形。

因此一般保留目标肢体骨骼的参考位移，传递源骨骼的旋转运动，并对骨盆、根骨骼等需要位移动画的骨骼进行单独处理。

## **面试题 5：UE 中 Animation、Skeleton 和 AnimationScaled 有什么区别？**

**重要程度：★★★★★**

|模式|面试回答|
|---|---|
|Animation|直接使用动画中的骨骼位移|
|Skeleton|使用目标骨骼的参考姿势位移|
|AnimationScaled|根据源与目标的参考骨骼长度比例，缩放动画位移|

传统人形骨架中，Root 通常使用 Animation，Pelvis 通常使用 AnimationScaled，大部分普通肢体骨骼使用 Skeleton。

需要强调的是，这是传统骨架位移重定向模式，并非 IK Retargeter 的全部实现。

## **面试题 6：FK 和 IK 有什么区别？为什么动画重定向需要 IK？**

**重要程度：★★★★★**

FK 是已知关节变换，计算末端位置。

IK 是已知末端目标位置，反向求解关节变换。

FK 重定向可以保留源角色的运动形态，但由于目标角色身体比例不同，手脚末端位置可能产生偏差。

IK 可以修正这种偏差，实现脚部贴地、武器握持、双手交互等效果。

实际项目中通常先进行 FK，再进行 IK 修正。

## **面试题 7：Two Bone IK 的底层原理是什么？**

**重要程度：★★★★★**

Two Bone IK 通过已知两根骨骼长度以及根关节到目标位置的距离，构建三角形，再利用余弦定理求出关节角度。

在三维空间中，需要通过 Pole Vector 或 Joint Target 确定关节弯曲方向。

它具有计算开销低、无需多次迭代的优点，常用于手臂和腿部。

如果目标位置超出最大可达距离，则需要限制目标距离，或者根据配置允许一定程度的骨骼拉伸。

## **面试题 8：如果源角色和目标角色的骨骼数量不同，如何重定向？**

**重要程度：★★★★★**

可以使用骨骼链映射，而不是强制一对一骨骼映射。

例如将源角色三节脊柱的运动映射到目标角色五节脊柱上。

通过归一化骨骼链参数、旋转采样插值、参考姿势校正等方式传递整条骨骼链的运动。

对于关键末端，还可以通过 IK 保证位置约束。

## **面试题 9：UE5 的 IK Rig 和 IK Retargeter 有什么区别？**

**重要程度：★★★★★**

IK Rig 用于描述单个角色的骨骼链、IK Goal 和 IK Solver 等配置。

IK Retargeter 用于建立源 IK Rig 和目标 IK Rig 之间的运动转换关系，处理骨骼链映射、姿势校正、FK、IK 以及根骨骼运动等。

一个负责描述角色自身骨架，一个负责角色之间的动画转换。

## **面试题 10：Reference Pose、Bind Pose 和 Retarget Pose 有什么区别？**

**重要程度：★★★★★**

|名词|作用|
|---|---|
|Reference Pose|参考姿势，骨架的基础变换数据|
|Bind Pose|绑定姿势，网格与骨骼建立蒙皮绑定时的姿势|
|Retarget Pose|重定向姿势，用于对齐源和目标骨架|

Reference Pose 和 Bind Pose 在常见资产中可能一致，但概念上不是完全相同的东西。

Retarget Pose 主要用于动画转换。例如将 T-Pose 角色的上臂调整到 A-Pose，以便与源角色的重定向姿势对齐。

调整 Retarget Pose 不等于重新进行网格蒙皮绑定。

## **面试题 11：动画重定向之后出现脚滑，如何解决？**

**重要程度：★★★★★**

首先检查动画步幅、角色实际移动速度和动画播放速度是否一致。

然后可以使用 Foot Locking 保持支撑脚的位置，使用 Foot IK 处理脚部与地面接触，使用 Stride Warping 调整步幅。

如果是重定向过程中末端轨迹不准确，还需要检查骨盆高度、IK Goal 和脚部锁定设置。

需要注意，Foot IK 主要解决接触位置问题，并不能自动解决所有脚滑问题。

## **面试题 12：动画重定向如何处理 Root Motion？**

**重要程度：★★★★★**

需要将 Root Motion 和普通肢体运动分开处理。

普通骨骼主要传递旋转和相对姿态，而 Root Motion 涉及角色整体移动距离和方向。

可以选择保留原始根运动、根据身体比例缩放，或者根据技能玩法指定的距离进行 Motion Warping。

对于攻击、闪避等技能，通常需要保证动画运动与游戏逻辑位移一致。

## **面试题 13：离线重定向和运行时重定向有什么区别？**

**重要程度：★★★★☆**

离线重定向在编辑器中提前生成目标动画资源，运行时可以直接播放，CPU 开销比较可控，但会增加资源数量。

运行时重定向是在姿势求值过程中实时转换骨骼姿势，可以减少重复动画资产并提高灵活性，但会增加运行时计算开销。

大型项目需要综合考虑动画资产数量、内存、CPU 性能和角色动态组合需求。

## **面试题 14：不同角色可以直接共享同一个 Skeleton 吗？**

**重要程度：★★★★★**

可以，但角色骨架需要满足 UE 的兼容要求。

通常应保持核心骨骼命名和父子层级一致，允许在兼容规则范围内存在额外的辅助骨骼。

不同角色的身体比例可以通过参考骨骼位移和相应的重定向机制适配。

如果骨骼结构差异较大，则更适合使用 IK Rig 和 IK Retargeter。

共享 Skeleton 并不意味着所有 Skeletal Mesh 的骨骼长度、模型和蒙皮数据必须完全相同。

## **面试题 15：动画重定向会影响蒙皮吗？**

**重要程度：★★★★☆**

会影响最终的蒙皮变形结果，但通常不会修改模型的原始蒙皮权重。

采用列向量矩阵约定，线性混合蒙皮公式为：

$$
v'=\sum_{i=1}^{n}w_i M_i^{pose}(M_i^{bind})^{-1}v
$$

其中：

$$
v：原始模型顶点。
$$
$$
w_i：骨骼对顶点的蒙皮权重。
$$
$$
M_i^{pose}：重定向之后的骨骼全局姿势矩阵。
$$
$$
(M_i^{bind})^{-1}：逆绑定矩阵。
$$
$$
v'：变形之后的顶点。
$$

动画重定向负责生成目标骨骼的姿势，蒙皮系统再根据这些骨骼姿势驱动目标模型顶点。

动画重定向和蒙皮是两个不同的计算阶段。

## **面试题 16：动画重定向如何进行性能优化？**

**重要程度：★★★★★**

可以从资产、算法、运行时三个方向进行优化。

资产方面，尽可能统一标准骨架，并对固定角色使用离线重定向。

算法方面，提前缓存骨骼映射关系、参考姿势、比例系数和坐标空间转换参数，避免重复计算。

运行时方面，根据角色重要程度和 LOD 减少 IK 求解、降低动画更新频率，并利用并行动画求值和动画预算机制控制整体开销。

## **面试题 17：动画重定向会影响攻击判定吗？如何处理？**

**重要程度：★★★★★**

会。

因为动画重定向可能改变角色肢体长度、武器位置和武器运动轨迹。

如果战斗逻辑仍使用原始角色的攻击轨迹，就可能导致视觉表现与攻击判定不一致。

可以使用最终骨骼姿势下的武器 Socket 进行扫掠检测，或者针对最终动画离线烘焙攻击轨迹，也可以使用独立的技能攻击判定配置。

在多人游戏中，需要确保服务器权威判定与客户端预测、动画表现之间具有明确的一致性策略。

## **面试题 18：如果让你设计一个大型动作游戏的动画重定向系统，你会如何设计？**

**重要程度：★★★★★**

首先建立统一的角色骨架规范，统一核心骨骼命名、层级、参考姿势、坐标轴、武器 Socket 和辅助骨骼定义。

其次，根据角色身体结构建立标准骨骼链映射，使用参考姿势校正、旋转转换、骨骼比例适配完成基础 FK 重定向。

然后针对手部握持、脚部接触、攀爬等关键动作使用 IK 修正，并使用 Foot Locking、Stride Warping 和 Motion Warping 解决运动匹配问题。

对于固定角色优先使用共享动画或离线重定向，对于动态角色使用运行时重定向。

最后通过动画 LOD、骨骼映射缓存、IK 求解优化、动画预算管理等方式降低运行时开销，并处理 Root Motion、攻击判定以及多人网络同步的一致性问题。

**最重要的是理解动画重定向的四个核心目标：**

1. 传递运动信息——源角色如何旋转和移动。
2. 保留骨骼结构——目标角色自身的骨骼长度和身体比例。
3. 消除骨架差异——参考姿势、坐标轴、骨骼数量和层级差异。
4. 修正末端位置——利用 IK 保证手脚接触、武器握持等效果。

对于 UE 游戏客户端面试，尤其是动作战斗系统方向，建议重点掌握**旋转重定向公式、位移重定向模式、FK 与 IK 的区别、Two Bone IK 原理、UE5 IK Retargeter、Root Motion、脚滑处理以及攻击判定一致性**这几个部分。
